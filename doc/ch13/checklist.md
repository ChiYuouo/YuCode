# 斜杠命令注册与分发 Checklist

## 使用与记录规则

本清单根据本章 spec、plan 和 task 编写，共 31 项：19 项功能验收、5 项集成验收、4 项测试与构建检查、3 项真实终端场景。用户已要求进入本阶段；本文件仍待审批，当前所有项目均未执行、未通过。

每项只有在操作实际执行、全部预期符合且证据可查时才能勾选。一个条目包含多个分支时，不能只验证成功分支便整体勾选；跳过、环境受阻和未执行均保持未勾选并说明原因。记录于 `verification.md`：条目 ID、实际命令或输入、预期、实际结果、退出码（适用时）、证据位置和最终状态。只有相关实现未再变化时，才能复用本次前序任务的有效测试证据。

自动测试使用隔离的临时项目、用户记忆和假模型。它们验证确定性分支与故障注入，不代替真实模型端到端验收。界面通知不应计入模型历史；已在运行的后台记忆请求与某条本地命令新触发的请求必须区分，不能只凭请求总数变化误判。

下文给出的是可观察行为；测试文件和筛选命令仅为当前执行入口，文件重命名后更新入口即可，不改变验收要求。所有 `-k` 筛选必须实际选中测试；零测试收集不算通过。此时不执行这些命令，待审批完成及实现后运行。

## 真实终端端到端场景

### E01：从真实对话贯通到恢复与确认删除（AC20）

- [ ] 通过

**准备：** 使用 T39 创建的独立临时 Git 项目、临时用户目录和真实模型配置；项目含 README 及一份可审查的未提交改动。在 Ubuntu tmux 中经 Windows PowerShell 启动 YuCode，记录实际进程启动命令和会话名。

**操作：**
1. 输入“请读取当前项目的 README 并说明这个示例做什么”，等待真实工具结果和最终回复；执行 `/status`。
2. 输入 `/pl` 并按 Tab，确认尚未切模式；回车后显示 `[PLAN]`，再执行 `/do` 显示 `[DEFAULT]`。
3. 执行 `/review`，观察对临时项目改动的只读检查和审查回复。
4. `/session` 记录 A 的实际 ID，`/session new` 得到 B，`/session list` 查到两者；通过 `/session resume <A的实际ID>` 恢复并追问。
5. 切到 B，再对 A 执行 `/session delete <A的实际ID>` 并明确确认；检查清单中 A 消失，B 仍能继续对话。

**预期：** 整段流程使用真实模型、真实终端和本次临时存档完成；可见工具调用及有效回复，补全不误执行，模式与状态一致，恢复后对话连贯，删除只作用于指定非活动测试会话。
**验证与证据：** 使用 `wsl -d Ubuntu -- tmux capture-pane -p -t <实际tmux会话名> -S -120` 分阶段采集输出，尖括号替换为记录的实际值；保留输入、工具结果、状态及会话清单，并对比测试文件和存档。仅能启动或模拟 Provider 通过均不能勾选此项。
