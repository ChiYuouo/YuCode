# 斜杠命令注册与分发 Spec

## 背景

YuCode 已有对话输入、计划模式、权限切换、上下文压缩和历史会话恢复能力，但命令判断与界面菜单分散维护，缺少统一的命令信息、参数处理和补全规则。

本章提供统一的斜杠命令入口，让确定性的操作直接执行，让需要 AI 的操作通过固定提示词进入对话。沿用已有上下文、会话、记忆和权限能力，不重新建设这些子系统。

## 目标

- 统一管理命令名称、别名、说明和执行行为，在启动时发现命名冲突。
- 让用户通过十条公开命令完成帮助、压缩、清屏、模式切换、会话管理、记忆辅助、权限设置、状态查询和改动审查。
- 使本地操作无需模型判断，命令补全、帮助与实际执行保持一致。
- 让命令行为独立于具体界面渲染框架，状态变化能立即反映在界面中。

## 功能需求

### F1：统一登记与启动校验

每条命令必须登记名称、别名列表、简短描述、用法示例和执行类别，并支持可选的参数提示、隐藏标记及处理行为。执行类别为纯本地、影响界面状态、预设提示词三类；可执行命令必须具备对应的处理行为。

名称与别名共用一个大小写不敏感的命名空间。启动时必须校验名称与名称、名称与别名、别名与别名之间的冲突，重复登记也算冲突；发现冲突必须报告冲突词及相关命令，并以失败状态退出，不进入可交互状态。

### F2：解析与输入分流

输入去除首尾空白后为空时直接返回，不执行命令，也不调用 AI。首字符不是 `/` 时沿用普通对话流程；首字符是 `/` 时必须先交给命令分发，不能将未知命令作为普通聊天发送。

斜杠后的第一个空白分隔符之前为命令名，后面的内容为参数；空格、制表符和换行均视为分隔符。命令名匹配不区分大小写，参数保留原有大小写和内部空白，仅去除参数首尾空白。不额外解释引号、变量或转义表达式。

单独输入 `/` 或输入未知命令并提交时，显示中文提示并引导使用 `/help`。缺少参数、多余参数和未知子操作显示对应命令用法，不产生部分操作。本文列出的固定子操作与权限选项也不区分大小写，会话 ID 按原值校验。

### F3：执行类别与界面解耦

纯本地命令直接查询状态或调用已有服务；影响界面状态的命令完成清屏、模式切换或会话切换等行为；预设提示词命令将固定提示内容作为用户消息送入正常对话。

命令通过统一的界面控制能力显示消息、发送用户消息、切换模式、查询 Token 和刷新状态，不依赖具体渲染组件。会话删除的确认也由界面承接。

本地命令文本和本地反馈不得加入模型对话历史或触发自动记忆提取。除已有压缩与恢复时必要的压缩外，本地和界面操作不发起模型请求。预设提示词命令只提交一次展开后的用户消息，沿用普通对话的工具权限、取消、持久化和自动记忆流程。

### F4：帮助、别名与补全

`/help` 展示全部公开命令的名称、别名、描述、用法和可用参数提示。`/help <命令名或别名>` 展示指定公开命令的详细用法，查询时允许省略或保留斜杠。`/?` 作为 `/help` 的公开别名。

命令名输入期间按 Tab，按名称及别名前缀进行大小写不敏感匹配：只有一个匹配命令时补为其完整主名称并追加一个空格；多个匹配时显示候选菜单，名称与别名命中同一命令时合并为一项。菜单支持上下选择、Enter 确认补全、Esc 关闭；确认补全不立即执行，再次提交才执行命令。无匹配时保持输入不变，不发送请求。

仅命令名区域参与补全；进入参数区域后不补全子操作、会话 ID 或文件路径，只显示登记的参数提示。隐藏命令及其别名不出现在帮助和补全中，但完整输入仍可执行。Shift+Tab 保留现有权限切换快捷操作。

### F5：十条公开命令

| 命令与用法 | 执行类别 | 可观察行为 |
| --- | --- | --- |
| `/help [命令]` | 纯本地 | 显示公开命令清单或指定命令的用法。 |
| `/compact` | 纯本地 | 调用已有手动压缩能力，显示进行中、成功或失败结果；成功时显示压缩前后估算 Token。摘要生成可能调用模型，但不启动普通工具对话。 |
| `/clear` | 影响界面状态 | 清空聊天区显示，保留当前会话 ID、内存对话上下文、存档和记忆；下一次追问仍可使用先前上下文。 |
| `/plan` | 影响界面状态 | 进入已有计划模式，后续 AI 对话受既有只读限制，状态栏显示 `[PLAN]`。 |
| `/do` | 影响界面状态 | 切回默认权限模式，状态栏显示 `[DEFAULT]`；不恢复进入计划模式前的自动批准或跳过审批设置。 |
| `/session [子操作]` | 影响界面状态 | 根据 F6 查询或管理当前项目的会话。 |
| `/memory [补充要求]` | 预设提示词 | 将固定的“查看并梳理当前项目记忆，说明已有内容、重复或待更新之处；没有明确修改要求时仅给出整理建议”请求送入对话。 |
| `/permission [模式]` | 影响界面状态 | 无参数时显示当前权限模式、可选模式及用法；带有效模式时立即切换并刷新状态。支持 `default`、`accept_edits`、`plan`、`bypass_permissions`，沿用现有各模式的权限语义。 |
| `/status` | 纯本地 | 显示模型与提供方、当前权限模式、当前会话 ID 与消息数、当前上下文估算 Token，以及最近一轮对话的输入、输出和缓存 Token。估算量明确标注，尚无统计或来源不提供的数据标为不可用。 |
| `/review [审查重点]` | 预设提示词 | 将固定的“审查当前工作区未提交改动，指出可验证的问题、位置、影响和建议；仅审查，不实施修复”请求送入对话。 |

`/memory` 和 `/review` 的可选参数作为补充要求原样附加在固定提示词之后，不按参数动态生成或选择模板。不支持参数的命令收到参数时显示用法。

公开命令固定为以上十条。已有 `/exit` 和 `/quit` 保留为同一隐藏退出命令及其别名，使用统一分发，不计入公开命令清单。原 `/resume` 入口由 `/session resume <会话ID>` 替代，不再单独提供。

### F6：会话管理

- `/session`：显示当前会话 ID 和当前上下文消息数；消息数按当前对话记录条数统计，不将界面通知算作消息，也不把消息数称为对话轮数。
- `/session list`：列出当前项目的会话 ID、标题、最近活动时间和可恢复消息数，并标出当前会话；历史清单的消息数来自存档，与压缩后的当前上下文消息数可能不同。空会话也显示 ID 和零消息数；没有记录时明确提示。
- `/session resume <会话ID>`：恢复指定会话的有效历史，成功后用该会话历史替换聊天区，后续消息写入被恢复的会话。沿用已有损坏记录处理、上下文超限压缩和时间跨度提醒。恢复当前会话时提示已处于该会话，不重复恢复；有效空会话可以恢复为干净上下文。
- `/session new`：创建并切换到新的唯一会话，清空聊天显示和当前对话历史，重置对话相关状态及最近一轮 Token 展示。保留项目指令、持久记忆、当前权限模式和旧会话存档；新对话不继承旧会话消息或恢复提醒。
- `/session delete <会话ID>`：先校验目标，展示目标会话概要和删除后无法通过会话恢复找回的提示，用户明确确认后才删除该会话存档。取消或关闭确认时不删除；删除成功后列表中不再出现该会话。不删除当前会话，提示先新建或切换到其他会话，再执行删除。

所有会话操作仅针对当前项目的合法会话 ID，不接受任意路径。不存在、格式无效或无法访问的目标应有明确中文提示。新建或恢复失败时保留原活动会话及上下文；删除失败时不得报告成功。切换或删除会话不能使旧会话的后台工作写入其他会话或重新生成被删除存档。

### F7：模式与状态联动

`/plan`、`/do`、`/permission` 与 Shift+Tab 使用同一权限状态。默认和计划模式分别显示 `[DEFAULT]`、`[PLAN]`，另两档分别显示 `[ACCEPT_EDITS]`、`[BYPASS_PERMISSIONS]`，不得以默认标记掩盖实际权限。

执行有效模式切换后，状态栏和 `/status` 必须立即一致；重复进入同一模式保持状态不变并给出可理解的反馈。清屏、压缩、新建和恢复会话后，状态展示必须对应当前实际会话。

### F8：忙碌、取消与失败

对话生成、工具审批、压缩、会话恢复和删除确认期间，不接受新的命令执行或重复提交。已存在的停止、审批响应和退出操作沿用原有交互，不将命令排队到未来执行。

普通命令执行失败以中文显示原因，应用仍可继续接收输入；不把失败命令改送 AI。压缩失败保留可用历史；提示词命令的模型失败或取消沿用普通对话处理。启动命名冲突属于启动失败，不按普通运行错误忽略。

## 非功能需求

- N1：确定性的帮助、查询、模式切换与清屏不等待模型，不增加模型 Token 消耗；压缩及恢复中必要的压缩明确作为例外。
- N2：帮助、补全和分发使用同一份登记信息；调整命令说明、别名或隐藏标记后，这三个入口表现一致。
- N3：使用中文提示；错误信息说明原因及适用的后续操作，不能仅展示内部异常。
- N4：命令行为可以通过替代界面验证，无需启动完整终端渲染框架；耗时操作应有可见反馈并保留既有停止能力。
- N5：沿用既有工具权限、会话恢复和记忆存储边界，提示词命令不得获得额外工具权限。

## 不做的事

- 不提供用户自定义命令、运行期插件注册或动态提示词生成。
- 不提供命令级权限控制；现有工具权限继续适用于 AI 对话。
- 不补全参数值、会话 ID 或文件路径。
- 不新增独立于现有权限状态的第二套计划模式。
- 不增加会话分支、合并、导出、跨项目迁移或删除回收站。
- 不重构既有压缩算法、持久记忆提取机制或存档格式。
- 不保证本地命令完全不调用模型：手动压缩和必要的恢复压缩继续使用现有摘要能力。

## 验收标准

- AC1（F1、N2）：分别登记名称重复、名称与别名冲突、两个别名冲突及仅大小写不同的冲突；每次启动均在接收输入前失败，报告冲突词和相关命令。无冲突的登记能正常启动。
- AC2（F2）：分别提交空白、普通对话、大小写混合命令、带多个空白的参数、单独 `/` 和未知命令；空白无操作，普通对话只发出一次请求，命令名正确匹配，参数内部内容保留，未知输入显示 `/help` 引导且不调用模型。
- AC3（F2、F5、F6）：分别提交缺失会话 ID、未知子操作、非法权限模式，以及给 `/clear` 等无参数命令附加参数；均显示对应用法，不改变会话、权限或聊天内容。
- AC4（F3、N1、N5）：执行帮助、状态、清屏、权限切换和不需压缩的会话操作；观察不到新增模型请求、模型对话记录或由这些操作触发的自动记忆任务。
- AC5（F3、F5）：执行 `/memory` 和 `/review`，各带一段有大小写与内部空白的补充要求；每次仅产生一条展开后的用户消息，固定提示内容和参数可见且进入存档，AI 沿用普通工具权限执行。无修改要求的记忆查看和审查不授权修改文件。
- AC6（F4、F5、N2）：执行 `/help`、`/?` 和指定命令帮助；看到十条公开命令及其描述、用法和参数说明。隐藏退出命令不展示；完整输入 `/exit` 或 `/quit` 仍正常退出；原 `/resume` 按未知命令提示。
- AC7（F4）：分别在单匹配、多匹配、别名、大小写混合和无匹配前缀处按 Tab；观察到直接补全、候选菜单、合并匹配及输入保留符合要求。菜单 Enter 只补全，Esc 只关闭；隐藏项不出现，参数区域不补全参数值。
- AC8（F5）：准备足够长的历史后执行 `/compact`；看到进度及压缩前后估算量，下一次对话使用压缩后的上下文。模拟摘要失败，看到失败提示且原可用历史仍保留；命令文本没有成为普通用户对话。
- AC9（F5）：先让 AI 记住一条仅存在于本轮对话的测试信息，再执行 `/clear`；聊天显示清空，会话 ID、上下文消息数和存档保持不变，下一次追问仍能引用该信息。
- AC10（F5、F7）：依次通过 `/permission accept_edits`、`/plan`、`/do` 和 Shift+Tab 切换模式；状态栏与 `/status` 一致，计划模式只能使用既有只读工具，`/do` 回到默认模式；重复切换同一模式无副作用。
- AC11（F5、F7）：在首轮对话前和完成一轮对话后执行 `/status`；模型、模式和会话概要正确，估算与实际用量明确区分，缺失用量标为不可用。执行本地命令不虚增用量。
- AC12（F6）：准备多个当前项目历史会话和一个空会话，执行 `/session` 与 `/session list`；当前概要、清单字段、空会话零消息数与当前标记正确，不展示其他项目会话。
- AC13（F6、F7）：执行 `/session resume <会话ID>` 恢复历史并继续追问；界面替换为所选历史，新回复利用该历史且追加到对应存档。恢复有效空会话得到空上下文；恢复当前会话不重复绘制或追加历史。
- AC14（F6、F8）：恢复带坏记录、超限或长时间间隔的历史；既有跳过坏记录、必要压缩和时间提醒仍有效。恢复无法完成或新建失败时，原会话 ID 与上下文保持可用。
- AC15（F6、F7）：执行 `/session new`；看到新 ID、零条上下文消息和重置后的对话用量，旧存档保留，项目指令、持久记忆及权限模式保留。下一次模型请求不带旧会话消息或恢复提醒。
- AC16（F6）：删除一个非当前会话；确认前存档存在，取消后仍可恢复，再次明确确认后清单中消失且无法恢复。删除当前会话被拒绝并提示先切换；非法、跨目录或不存在目标均不会删除其他内容。
- AC17（F6）：在旧会话有后台记忆工作时切换并删除该非活动会话；等待后台工作结束，观察新会话没有被追加旧会话消息，删除的存档没有重新出现。
- AC18（F8、N3、N4）：在生成、审批、压缩、恢复和删除确认期间尝试重复提交或其他命令；没有并发执行或之后的延迟执行，已有停止与审批交互仍可用。模拟普通命令服务失败后，用户看到中文原因且仍可继续输入。
- AC19（F3、N4）：通过替代界面执行本地查询、模式切换与提示词发送；无需终端渲染即可观察到正确消息、状态刷新和一次提示词提交。
- AC20（整体）：在 tmux 中启动 YuCode，完成“真实对话 → `/status` → Tab 补全 `/plan` 并提交 → `/do` → `/review` 触发只读工具 → `/session new` → 历史恢复 → 二次确认删除非当前会话”的端到端流程，对照以上标准记录实际结果。
