# 持久记忆与会话恢复 Checklist

> 每项均以可观察行为验收；`<项目目录>` 表示临时测试项目，`<用户目录>` 表示测试隔离的用户配置目录。

## 项目指令与安全引用

- [ ] 三层指令按优先级注入首个请求（AC1）。验证：在 `<项目目录>/YUCODE.md`、`<项目目录>/.yucode/YUCODE.md`、`<用户目录>/.yucode/YUCODE.md` 写入不同标记，启动后用假 Provider 捕获首个请求。预期：三个标记均在稳定提示中，顺序为项目根、项目配置、用户配置。
- [ ] 有效嵌套引用被展开（AC1）。验证：项目根指令用 `@include` 引用项目内的另一 Markdown 文件，捕获首个请求。预期：被引用内容出现在指令位置，引用行本身不作为普通规则发送。
- [ ] 环路、过深、缺失和越界引用安全降级（AC1）。验证：分别构造循环引用、深于五层的引用、缺失文件和 `../` 越界引用后启动。预期：有效内容仍生效；每个无效引用有中文 warning；项目目录外文件内容绝不进入提示。

## 会话创建、记录与列表

- [ ] 每次启动创建唯一新会话（AC2）。验证：在同一秒内连续调用启动装配两次并列出 `.yucode/sessions/`。预期：出现两个格式为 `YYYYMMDD-HHMMSS-xxxx.jsonl` 的不同文件。
- [ ] 对话和工具活动完整追加为 JSONL（AC2）。验证：进行一轮用户消息、带工具调用的助手消息、工具结果和最终助手消息，逐行解析对应存档。预期：每行独立有效 JSON，载荷保留调用参数、结果正文、成功状态、摘要、错误码和目标。
- [ ] 截断末行不会破坏既有历史（AC2、AC4）。验证：从上述 JSONL 删除最后一行的一部分再恢复。预期：此前完整消息仍恢复，恢复结果报告坏行 warning。
- [ ] `/resume` 显示可识别的当前项目历史会话（AC3）。验证：准备至少两个有不同首条用户消息和活动时间的会话后执行 `/resume`。预期：列表含每项的 ID、派生标题、最近活动时间、消息数，且按最近活动优先。
- [ ] 选择会话后历史成为后续请求上下文（AC3）。验证：恢复含唯一历史事实的会话，发送追问并捕获模型请求。预期：请求历史含该事实；新回复能够基于该事实回答。

## 恢复容错与上下文保护

- [ ] JSONL 中间坏行被跳过而非中断恢复（AC4）。验证：在两段有效记录中插入无效 JSON 行后恢复。预期：坏行前后的可用消息都被恢复，warning 明确指出已跳过记录。
- [ ] 未配对工具调用后的历史被截断（AC4）。验证：创建“助手工具调用 → 无对应结果 → 后续消息”的存档并恢复。预期：工具调用之前的历史保留；该调用及后续不进入恢复上下文，并有中文 warning。
- [ ] 工具结果 ID 不匹配时同样截断（AC4）。验证：让工具结果的调用 ID 与前一助手调用不一致。预期：从该助手调用开始的消息不恢复。
- [ ] 恢复的超长历史只压缩一次（AC5）。验证：恢复估算超过自动安全线的历史，使用记录摘要请求次数的假 Provider。预期：恢复过程仅请求一次摘要，然后才允许普通对话。
- [ ] 一次压缩后仍超限时不请求正常模型（AC5）。验证：让恢复压缩后的估算仍超过安全线。预期：界面显示明确中文失败原因，当前新会话仍可使用，正常 Provider 未收到用户请求。
- [ ] 长时间间隔只为下一请求添加提醒（AC5）。验证：恢复最后活动时间至少 24 小时前的会话，连续发送两条消息并捕获 runtime message。预期：第一条有时间跨度提醒，第二条没有；原 JSONL 不出现该提醒。
- [ ] 普通新会话维持既有超限重试行为（AC5）。验证：在非恢复会话中模拟首次 `context_length_exceeded`，随后摘要成功。预期：按既有行为执行一次紧急压缩并重试原请求。

## 自动笔记与长期记忆

- [ ] 自然结束后异步提取四类笔记（AC7）。验证：以假 Provider 完成包含偏好、用户纠正、项目事实和参考资料的四轮对话，并让笔记模型依次返回四类动作。预期：最终回复无需等待笔记任务；随后出现四条正确类别的独立 Markdown 笔记。
- [ ] 笔记按范围保存且包含元数据头（AC7）。验证：分别让笔记模型产出用户级偏好和项目级知识。预期：前者在 `<用户目录>/.yucode/memory/`，后者在 `<项目目录>/.yucode/memory/`；每条含 ID、范围、类别、创建/更新时间和标题。
- [ ] 重复笔记不新增冗余文件（AC7）。验证：已有一条对应笔记，笔记模型返回更新或忽略动作。预期：更新时仅原文件变化；忽略时文件和数量不变。
- [ ] 非自然停止不调度笔记（AC7）。验证：分别模拟取消、Provider 错误、迭代上限、未知工具和验证未完成。预期：没有记忆模型请求，也没有新笔记文件。
- [ ] 两级索引在请求前注入上下文（AC8）。验证：各准备一个用户级和项目级 `index.md` 后启动并发送首条请求。预期：捕获的稳定提示同时含两份索引，并能据其中内容影响回复。
- [ ] 索引永不超过 200 行或 25 KB（AC8）。验证：持续写入大量笔记直到任一限制被触发。预期：重建后的索引满足两个上限，且仍保留类别摘要和原笔记 ID 引用。
- [ ] 索引压缩失败仍保持可用上限（AC8、AC9）。验证：让索引压缩模型失败或超时。预期：索引按降级规则受限，原笔记文件不丢失，诊断队列出现中文提示。
- [ ] 笔记后台失败不影响主对话（AC9）。验证：让笔记模型抛出错误或超时，完成一轮无工具回复后继续发送下一条。预期：两次主对话都能完成，界面显示可理解的后台失败信息，不需要重启。

## 会话清理与边界

- [ ] 30 天以上非当前会话被清理（AC6）。验证：准备有效最近活动时间分别为 31 天前、30 天前、近期和当前的会话，运行启动清理后列出目录和 `/resume`。预期：仅 31 天前的非当前会话删除且不再列出，其他三个保留。
- [ ] 清理不会删除非会话或目录外文件（AC6、N4）。验证：在会话目录放置不符合会话命名的文件，并给清理接口传入含路径分隔符的伪造 ID。预期：非会话文件未变，越界 ID 被拒绝，不发生目录外删除。
- [ ] 所有持久化文件可人工阅读和备份（N1、N2）。验证：打开 JSONL、三层指令、各级笔记和索引。预期：均为 UTF-8 文本，JSONL 每行可单独解析，Markdown 可直接阅读。

## 回归、构建与集成

- [ ] 自动化测试全部通过。验证：运行 `pytest -q`。预期：退出码为 0，既有 Provider、MCP、工具、权限、上下文和 TUI 测试均通过。
- [ ] 补丁没有空白错误。验证：运行 `git diff --check`。预期：无输出，退出码为 0。
- [ ] 启动装配不破坏既有 Provider 与 MCP。验证：分别用 OpenAI 和 Anthropic 最小配置启动，并声明一个可用和一个无效 MCP Server。预期：正确选择 Provider；可用 MCP 工具完成注册；无效 Server 仅显示中文 warning；持久化组件仍可用。

## 端到端场景

- [ ] 场景：新会话积累记忆并恢复历史。验证：
  1. 在临时项目写入项目根和项目配置 `YUCODE.md`，在隔离用户目录写入用户级 `YUCODE.md` 与一条用户记忆索引。
  2. 用 tmux 启动 YuCode，输入一段真实请求，例如“记住我偏好简短中文回答；阅读 README 并告诉我项目名称”。
  3. 观察模型请求含三层指令与记忆，工具/回复正常显示；等待自然结束后的后台笔记完成。
  4. 退出并重新在 tmux 启动 YuCode，确认新 JSONL 会话出现；输入 `/resume`，选择上一次会话。
  5. 继续问“我刚才要求的回答风格是什么？项目名称是什么？”。

  预期：第二次启动默认是新会话；`/resume` 列表可选择旧会话；恢复后历史可追溯，回答能引用已存偏好和项目事实；无未处理错误，所有生成与工具调用正常完成。
