# 持久记忆与会话恢复 Spec

## 背景

YuCode 当前的项目上下文和对话历史仅在单次运行期间有效。用户每次重新启动后，都需要重新说明项目约束、个人偏好和此前的工作进展；中断的工具调用也无法安全地继续使用。

本功能为 YuCode 增加分层的项目知识、会话存档和自动笔记能力。每次启动创建一个新会话，但在处理请求前自动加载适用的项目指令和记忆索引；用户可通过 `/resume` 从历史会话列表中主动选择一个会话恢复继续工作。

## 目标

- 让新会话在首个请求前自动获得用户偏好、项目规则和已有项目知识。
- 可靠保存对话，使程序退出或崩溃后仍可查看并恢复历史会话。
- 在不依赖向量数据库的前提下，把长期记忆保持为小而可读、可维护的 Markdown 文件。
- 对损坏存档、未完成工具调用、上下文超限和长时间中断提供可预期的恢复行为。

## 功能需求

- F1：启动时，系统必须从用户级、项目级和项目隐藏配置目录加载名为 `YUCODE.md` 的手写项目指令，并将更高优先级的内容置于更前面，使其在发送首个请求前即对 Agent 生效。缺失的指令文件不得阻止启动。
- F2：项目指令文件必须支持引用同一项目目录内的其他指令文件；引用不能无限嵌套、不能形成循环，也不能读取项目目录以外的文件。遇到无效引用时，系统必须跳过该引用并向用户给出可理解的提示，其他有效指令仍继续生效。
- F3：每次启动必须默认新建一个独立会话，并在所属项目的会话存档目录中持续追加保存用户消息、Agent 回复和工具调用/结果。会话标识必须在短时间内连续创建时也保持唯一。
- F4：用户可通过 `/resume` 查看当前项目的历史会话列表；列表必须显示可供识别的会话信息（至少包括 ID、标题、最近活动时间和消息数），并能选择一个会话恢复。恢复后，后续对话必须建立在该会话的有效历史之上。
- F5：恢复历史会话时，系统必须跳过损坏或不完整的单条存档记录，并保留此前和其后的可用记录；若工具调用没有对应结果，则从该未完成调用开始舍弃后续不可信记录。恢复过程不得因单个坏行导致整个会话不可用。
- F6：恢复后的有效历史超过模型可接受上下文时，系统必须先执行一次既有的上下文压缩，再发起模型请求；如果仍无法满足上下文限制，应明确告知用户而不是无限重试。
- F7：恢复的会话若距上次活动已有明显时间跨度，系统必须在发送下一次请求前向 Agent 提供一条时间跨度提醒，避免将过期状态当作最新状态。
- F8：系统必须定期清理超过 30 天、且不再是当前活动会话的过期会话存档；清理后不应在 `/sessions` 中出现已删除会话。
- F9：每轮 Agent 在自然结束（最终回复不再请求工具）后，系统必须异步分析本轮对话，并按用户偏好、纠正反馈、项目知识、参考资料四类更新自动笔记。自动笔记失败、超时或模型不可用不得影响已经显示给用户的最终回复。
- F10：自动笔记必须区分用户级与项目级存储：跨项目适用的用户偏好保存为用户级笔记，项目相关知识保存为项目级笔记；每条笔记必须是带元数据头的独立 Markdown 文件，并分别维护索引。
- F11：在每个用户请求送入 Agent 前，系统必须加载适用的用户级和项目级记忆索引并注入上下文，使 Agent 可直接利用已有记忆。每份索引必须受 200 行和 25 KB 上限约束；超过上限时应整理或缩减索引，而不是无界增长。

## 非功能需求

- N1：会话存档必须采用可追加、可从局部损坏中恢复的纯文本记录格式；单条追加未完成时，已完成历史仍须可读取。
- N2：项目指令、会话存档和自动笔记均应使用用户可直接查看、编辑和备份的文本文件。
- N3：与记忆相关的后台处理不得阻塞正常流式回复、工具执行或新请求处理；发生异常时必须保留诊断信息并以中文说明可操作的问题。
- N4：新功能不得改变现有项目边界和权限规则；引用指令文件与读取存档时均不得借此访问项目目录之外的项目文件。

## 不做的事

- 不引入向量数据库、语义检索或 RAG 检索流程。
- 不同步团队成员之间的记忆，也不提供远程记忆服务。
- 不在本章实现会话分支、合并、导出或跨项目迁移。
- 不保证从已经被清理的过期会话中恢复内容。
- 不自动恢复最近会话；每次启动默认建立新会话，恢复历史会话必须由用户通过 `/resume` 主动选择。

## 验收标准

- AC1（F1、F2、N4）：分别准备三层名为 `YUCODE.md` 的项目指令和有效/无效的引用。启动后首个模型请求可观察到三层有效内容按优先级生效；循环、超深或越界引用被跳过并有中文提示，未读取项目外文件。
- AC2（F3、N1、N2）：连续快速启动并进行多轮含工具调用的对话。观察到每次均创建唯一新会话，存档持续追加且可直接阅读；人为截断最后一条记录后，之前完成的对话仍可恢复。
- AC3（F4）：执行 `/resume`。观察到当前项目历史会话显示 ID、标题、最近活动时间和消息数；选择其中一个会话后，新回复能够引用其有效的先前对话。
- AC4（F5）：构造含坏行和未配对工具调用的存档后恢复。观察到坏行被跳过；未配对调用之前的历史可用，而该调用及其后的不可信记录不进入恢复后的上下文。
- AC5（F6、F7）：恢复一个超出上下文预算且距上次活动已有明显时间跨度的会话。观察到仅先压缩一次历史，并向 Agent 提供时间跨度提醒；若仍超限，用户获得明确错误提示且不发生重复重试。
- AC6（F8）：准备 30 天前和近期的会话，在触发定期清理后查看会话列表。观察到过期的非活动会话已被删除，近期和当前活动会话保留。
- AC7（F9、F10）：完成包含用户偏好、用户纠正、项目事实和参考资料的多轮对话。观察到最终回复无需等待笔记处理；随后对应类别的笔记以独立 Markdown 和元数据头保存到正确的用户级或项目级位置，重复信息不重复增加。
- AC8（F11）：在处理新请求前准备用户级和项目级记忆索引。观察到二者均进入 Agent 上下文并影响回复；持续累积笔记后，索引仍不超过 200 行和 25 KB。
- AC9（N3）：模拟自动笔记模型失败或超时。观察到主对话仍完成并正常展示最终回复，用户得到可理解的后台笔记失败提示或诊断，后续对话可继续。
