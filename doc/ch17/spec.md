# Git Worktree 隔离与子 Agent 集成 Spec

## 背景

YuCode 已具备子 Agent 与后台任务能力，但子 Agent 与主 Agent 仍在同一工作目录中读写文件。多个任务同时修改同一仓库时，容易互相覆盖或受到未提交改动影响。本章需要基于 Git 的多工作目录能力，为需要隔离的任务提供独立工作目录，使主 Agent 与子 Agent 能在同一仓库的不同分支上安全并行工作。

LLM 参与生成工作目录名称，因此名称和路径均不可信。系统还需要在创建、进入、退出、恢复、删除和后台清理的全生命周期中保护用户的代码和工作目录。

## 目标

- 为 Git 仓库中的独立任务创建、使用、恢复、列出和安全移除隔离工作目录。
- 确保不可信名称不能逃逸到受控工作目录之外。
- 在新工作目录中按项目规则补齐可运行的本地环境。
- 持久化当前工作目录会话状态，并支持恢复。
- 让声明需要隔离的子 Agent 自动在独立工作目录中执行，并将其路径作为上下文通知给 Agent。
- 提供用户可直接操作的 `/worktree` 命令。

## 功能需求

### F1：安全的名称与路径处理

系统应只接受符合受限字符集和长度限制的工作目录名称。名称可使用斜杠表达受控根目录下的嵌套层级，但不得包含空段、`.` 段、`..` 段、绝对路径、平台路径分隔符混用或其他可使路径离开受控根目录的形式。

在创建、查询、进入、退出、恢复和删除的每一条路径上，系统都必须在执行文件系统或 Git 操作前验证名称及最终解析路径仍位于当前仓库的受控工作目录根目录内。验证失败时应拒绝操作、不给 Git 传入不可信路径，并以中文说明原因。

### F2：Worktree 完整生命周期

用户或系统应能够创建、进入、退出、列出和移除工作目录。工作目录必须位于当前 Git 仓库内且被 Git 忽略的 `.yucode/worktrees/` 专用根目录。创建时应为该工作目录建立独立分支与目录；进入后，后续与项目相关的工具调用应显式使用该目录作为工作目录，而不是通过改变应用进程的当前目录实现切换；退出后恢复到主仓库工作目录。

若请求创建的目录已经存在且其文件系统状态可用于恢复，系统应进行快速恢复：只读取和验证本地状态，不再次执行创建或修改 Git 状态的操作。列表应显示可区分每个工作目录所需的信息，包括名称、目录、分支、是否为当前目录、状态与最后使用时间。

移除时，系统必须先检查未提交修改及未推送提交。默认情况下，发现任一种受保护变更时拒绝移除并给出中文原因；用户可明确要求强制移除来绕过该保护。移除 Worktree 默认只删除工作目录，保留其本地分支，供用户后续 merge 或检查；结果必须明确显示保留的分支名。用户仅在同时明确指定删除分支的选项时，才可丢弃该分支及其中未合并提交。自动清理不得强制移除有受保护变更的工作目录。

工作目录删除成功后，系统应从已删除目录向上清理 `.yucode/worktrees/` 内不再包含文件或子目录的空父目录，但不得删除受控根目录本身或 `session.json`。

### F3：创建后的环境初始化

每个新建工作目录应在创建成功后完成项目所需的初始化：按项目配置中的 `worktreeinclude` 规则复制本地配置文件与虽被 Git 忽略但项目运行所需的文件、配置该工作目录可用的 Git hooks，以及为大型可复用依赖目录建立软链接。`worktreeinclude` 应能逐项声明复制或链接的仓库内相对路径；文件与目录均可作为规则目标，规则不得引用受控范围外的路径。

初始化规则应支持项目配置，并对每一项来源和目标进行安全校验，防止越过主仓库或工作目录的受控范围。某项可选初始化资源不存在时，应有可理解的中文提示且不影响其他安全的初始化步骤；初始化失败时应报告失败项目与原因，且不得把未完成初始化的目录伪装为可用。

### F4：会话状态持久化与恢复

系统应将工作目录会话持久化到项目配置中，至少记录当前工作目录、可恢复工作目录的标识、目录、关联分支、创建和最后使用时间，以及自动清理所需的临时属性。

用户以恢复选项启动 YuCode 时，系统应读取已保存的会话并验证目标目录、仓库关联和安全路径；验证成功后恢复该目录作为后续项目操作的工作目录，验证失败时保持在主仓库并以中文说明原因。已移除或无效的记录不得被恢复，并应被安全地忽略或清理。

### F5：显式工作目录与缓存隔离

系统不得通过改变应用进程当前目录来切换工作目录。所有工具执行都应接收明确的工作目录；所有与路径有关的内容缓存、系统提示项目上下文、项目指令和记忆都应使用绝对路径作为键，使不同工作目录的数据天然隔离。

进入、退出或恢复工作目录时，不应依赖“清空所有缓存”来保证正确性；同一仓库下的不同工作目录读取相同相对路径时，系统必须不会混用内容、指令或记忆。

### F6：子 Agent 的隔离模式

Agent 角色定义应支持通过 frontmatter 的 `isolation: worktree` 明确声明工作目录隔离需求。主 Agent 的固定委派工具还应支持在单次调用中显式指定隔离模式；未指定时使用角色定义的默认值，显式指定时以调用值为准。工具只接受不隔离和 Worktree 隔离两种明确值；非法值必须被中文拒绝，不得静默降级为主目录执行。

声明或单次指定隔离的子 Agent 开始执行前，系统应自动创建或恢复其专用工作目录，并通过 `worktree_notice` 运行时上下文通知向该子 Agent 注入已分配的绝对目录、分支和隔离规则。系统提示和工具说明应让模型能将用户提出的“隔离执行”“使用 Worktree”“不影响主目录”等明确要求映射为该调用参数。

该子 Agent 的所有项目文件和命令工具调用必须显式使用其专用目录，不能落入主 Agent 当前目录或其他 Agent 的工作目录。子 Agent 完成后，系统应根据变更状态决定处理方式：无受保护变更的临时目录可以自动清理；存在未提交修改或未推送提交时必须保留，并在完成通知中说明目录、分支和保留原因。自动处理失败不得丢失 Agent 的最终结果或影响主会话继续运行。

### F7：过期临时目录清理

系统应在后台定期检查已标记为临时且超过配置保留期的工作目录。清理前必须同时验证：记录属于当前仓库的 `.yucode/worktrees/` 受控根目录、目录确为已登记的工作目录、且不存在未提交修改与未推送提交。三项验证任一失败时不得删除，并应保留或标记该记录供用户查看。Git 状态、推送状态或登记信息任一无法读取、超时或无法确认时，也必须按失败关闭原则跳过删除，不能推测其安全。

后台清理只处理临时目录，不得移除用户手动创建或明确保留的工作目录；清理行为及跳过原因应可通过用户可见的状态或日志追溯。

### F8：`/worktree` 命令

系统应提供不发送给模型的 `/worktree` 命令及 `list`、`create`、`enter`、`exit`、`remove` 五个子命令。

`list` 显示已登记工作目录；`create` 创建并初始化指定名称的工作目录；`enter` 切换当前会话到指定工作目录；`exit` 返回主仓库；`remove` 在默认变更保护下移除指定目录，并仅在用户明确使用强制选项时绕过手动删除保护。`remove` 默认保留分支；只有明确的删除分支选项才删除对应分支。缺少参数、名称非法、目标不存在、当前仓库不支持或操作失败时，界面必须给出中文且可操作的反馈。

## 非功能需求

- N1：所有工作目录名称、路径与删除操作遵循安全优先原则；任何不可信输入不得造成路径遍历、受控目录外访问或受控目录外删除。
- N2：Git、文件系统和初始化异常必须转换为中文、可定位的错误；异常不得导致主会话崩溃或遗失已持久化的有效会话状态。
- N3：创建、快速恢复、变更保护、初始化、会话恢复、缓存隔离、子 Agent 集成、自动清理和 Slash 命令均应有不依赖真实模型服务的自动化测试。
- N4：工作目录功能不得降低现有的项目根目录安全边界、权限确认、子 Agent 工具限制或后台任务通知语义。
- N5：用户可见的工作目录目录位置固定为仓库内、被 Git 忽略的 `.yucode/worktrees/`，并共享该仓库的 Git 对象数据库。

## 不做的事

- 不提供工作目录之间的自动合并、冲突解决或变更选择策略；用户自行决定合并或丢弃分支。
- 不提供跨工作目录的文件、补丁或代码同步工具。
- 不提供多 Agent 并行编排、任务图、调度或团队协作协议。
- 不复制大型依赖目录本身，也不承诺任意操作系统、文件系统或依赖目录都支持软链接；不支持时应明确报告。
- 不将工作目录会话、清理任务或 Agent 任务扩展为跨仓库共享服务。

## 验收标准

- AC1（F1）：分别使用合法嵌套名称、过长名称、空段、`.`、`..`、绝对路径、反斜杠及含非法字符的名称创建、进入和删除，验证只有合法名称可继续；所有非法输入均在调用 Git 或文件系统变更前被中文拒绝，且受控根目录外没有新增、读取或删除的目标。
- AC2（F2）：在 Git 仓库中创建工作目录并进入、退出、列表和移除，验证每个目录有独立分支，当前会话工具调用使用目标目录且主目录不被切换；重复创建已有目录时验证只读取并恢复状态，不触发新的 Git 创建操作。分别制造未提交修改与未推送提交，验证默认移除被拒绝；明确强制移除时验证指定目录被移除而其他目录不受影响、分支被明确保留；明确同时指定删除分支时验证目标分支及其提交被删除。验证删除后只清理空父目录，`.yucode/worktrees/session.json` 保留。
- AC3（F3）：配置 `worktreeinclude` 的文件复制、目录复制和依赖软链接规则，以及 hooks 后创建工作目录，验证各项按规则在受控目标中可用；尝试受控范围外路径时验证规则被拒绝。缺失的可选资源与初始化失败均显示中文原因，且该目录不会被错误标记为已成功初始化。
- AC4（F4）：进入工作目录后重启并使用恢复选项，验证恢复到同一目录且状态信息正确；删除目标或篡改保存记录后恢复，验证系统保持主仓库、报告中文原因且不访问不安全路径。
- AC5（F5）：在主目录和两个工作目录中对同一路径写入不同内容、项目指令和记忆，然后交替执行项目相关工具，验证每次读取和提示只反映当前显式目录的数据，且进程当前目录不因 enter、exit 或恢复而变化。
- AC6（F6）：定义一个带有 `isolation: worktree` 的子 Agent 并运行任务，验证其开始前获得 `.yucode/worktrees/` 下的专用目录，所有文件和命令工具调用使用该目录，且 `worktree_notice` 运行时上下文包含目录与分支说明。再对默认不隔离的角色，在单次委派工具调用中显式指定 Worktree 隔离，验证同样创建隔离目录；未指定时验证仍使用角色默认值。以非法隔离值调用时，验证得到中文失败且不创建任务或目录。分别以无变更、未提交修改和未推送提交结束，验证无变更临时目录自动清理，有受保护变更的目录被保留并在任务完成通知中说明原因和位置。
- AC7（F7）：创建多个临时、手动保留、有未提交修改、有未推送提交、登记缺失、Git 状态检查失败及受控根目录外伪造记录的过期候选项，执行后台清理，验证只删除属于当前仓库 `.yucode/worktrees/`、已登记且无受保护变更的临时目录；其余项均保留并可追溯跳过原因。
- AC8（F8）：在终端分别执行 `/worktree list`、`create`、`enter`、`exit`、`remove`、强制移除及明确删除分支的移除，验证对应结果正确显示且命令文本未发送给模型；验证普通移除与强制移除均显示保留分支，只有删除分支选项实际丢弃分支。验证缺少参数、非法名称、未知名称、非 Git 仓库、受保护变更和初始化失败时均得到中文、可操作的反馈。
- AC9（整体）：在 tmux 中启动 YuCode，输入一段真实的隔离子 Agent 请求，观察 YuCode 创建隔离工作目录、子 Agent 在其中完成文件操作并通知主会话；再用 `/worktree list` 检查状态，退出或移除该目录，并按本章 checklist 逐项记录实际结果。
