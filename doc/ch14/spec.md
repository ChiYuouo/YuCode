# Skill 能力包 Spec

## 背景

YuCode 已支持普通对话、工具调用、会话管理和斜杠命令，但用户若要重复执行一类 AI 操作，仍需反复输入相同的提示词和工具使用约束。项目需要一种可复用、可覆盖、可按需加载的 Skill 能力包机制，使用户能够把经过验证的操作流程以文件形式保存、共享和执行。

Skill 的目标是减少重复提示词并帮助模型在适当的时候选择正确工具；它不是市场、插件仓库或版本管理系统。

## 目标

- 让用户以带元信息的 Markdown 文件定义可复用 AI 操作，并以目录形式携带该操作专属的工具。
- 让模型在对话开始时只知道可用 Skill 的名称和简短用途，在需要时才加载完整指令和专属工具。
- 让多个已加载 Skill 的指令持续、醒目地出现在后续每轮对话的环境上下文中。
- 让 Skill 既可在当前对话中执行，也可在隔离对话中完成后只回流摘要。
- 通过 Skill 声明的工具白名单减少模型当前可见的工具集合，同时始终保留系统级的 Skill 加载能力。
- 支持本地修改后无需重启即可使用最新的 Skill 定义，并提供 `commit`、`review`、`test` 三个内置样板。

## 功能需求

### F1：Skill 定义与目录能力包

每个 Skill 的入口均为一个 Markdown 定义：文件开头使用 YAML frontmatter 声明唯一名称、一句话说明、`allowedTools` 可见工具白名单、执行模式、独立执行时携带的历史范围，以及可选的指定模型；正文为交给模型执行的 SOP 指令。

正文可引用一个公开、固定格式的参数占位符。用户通过短命令或模型发起加载后提供的参数会原样替换该占位符；未提供参数时替换为空文本，不把占位符原样交给模型。

Skill 既可作为单个入口文件存在，也可作为目录能力包存在。目录能力包以 `SKILL.md` 作为入口和 SOP 文档，可包含补充提示内容、`tool.json` 形式的专属工具描述与实现脚本，以及 `references/` 资源；这些专属工具必须拥有可供模型理解的名称、说明和输入约束。入口以外的文件、资源和脚本不单独成为 Skill。目录型 Skill 的资源只有在该 Skill 激活后才能按 SOP 使用。

同一 Skill 名称在同一来源内不得重复。名称必须能够安全地用于 `skill:` 前缀短命令；不符合命名规则的定义视为解析失败。

### F2：发现、优先级与容错

YuCode 从项目目录、用户目录和应用内置目录发现 Skill。三层优先级固定为：项目目录高于用户目录，用户目录高于内置目录。同名 Skill 只保留优先级最高的一份，并在目录变更后重新按该规则计算。发现和重新发现只读取文件，不要求重新编译或重启应用。

单个入口文件的 YAML、字段、正文、目录结构或专属工具定义无法解析时，YuCode 跳过该 Skill，显示中文警告并继续发现其他 Skill；一个损坏 Skill 不得阻止应用启动或其他 Skill 使用。被更高优先级的同名 Skill 覆盖的低优先级定义不应出现在可用列表中。

定义有效但其工具白名单引用了本次启动可识别范围之外的工具时，YuCode 必须在进入交互前以中文明确报错并拒绝启动。这一校验涵盖普通可用工具和目录能力包声明的专属工具；被跳过的损坏定义不参与校验。

### F3：两阶段加载与持续上下文

每次新对话开始时，模型只获得当前可用 Skill 的名称和一句话说明，不获得正文 SOP、参数内容或未激活 Skill 的专属工具。可用 Skill 列表应说明如何请求系统级加载能力。

模型可通过一个内置的系统级 Skill 加载工具，请求加载某个可用 Skill 并传入可选参数。加载成功后，YuCode 向模型提供该 Skill 的完整 SOP、完成参数替换后的内容、执行设置和已注册的专属工具；加载不存在、被跳过或参数不合法的 Skill 时，返回明确错误且不改变现有激活状态。

已激活 Skill 的完整指令必须在每轮重建环境上下文时持续出现，并处于比普通历史消息更醒目的环境指令位置。多个 Skill 可以同时激活；上下文中应清楚标识每项指令所属 Skill 和激活参数，避免把不同 SOP 混淆。重复加载同一 Skill 时更新为最新加载参数和定义，而不是累积重复指令。

Skill 加载工具属于系统级能力，始终可用且不受任何 Skill 工具白名单限制。

### F4：工具白名单与可见范围

Skill 的白名单定义该 Skill 激活时允许模型使用的普通工具。没有任何 Skill 激活时，模型沿用 YuCode 原有的普通工具可见范围；激活一个或多个 Skill 后，模型可见的普通工具为所有已激活 Skill 白名单的并集，并加上这些 Skill 已加载的专属工具。

白名单只影响模型本轮可见和可调用的普通工具，不绕过既有权限确认、计划模式或工具本身的错误处理。未在当前范围内的普通工具不得发送给模型，也不得由模型调用。每轮环境还必须把当前白名单中的工具以明确的“建议工具”提示呈现给模型，帮助模型在可用范围内优先选择合适工具。系统级 Skill 加载工具不属于普通工具范围，不因白名单、执行模式或模型指定而消失。

若热更新使已激活 Skill 的白名单或专属工具发生变化，下一轮对话必须立即按更新后的有效范围重建；若更新后无法解析，则保持最后一次有效的已激活定义并显示中文警告，直到用户清除它或出现新的有效定义。

### F5：两种执行模式

Skill 定义可以选择共享模式或独立模式。

共享模式在当前主对话中执行：用户的调用、模型的推理结果、工具调用和最终回复均按普通对话进入主历史，后续对话可以直接引用这些内容。

独立模式创建隔离的执行对话来完成任务。该对话始终带有当前项目的基础环境和被调用 Skill 的完整指令，并按 Skill 元信息选择带入零轮、最近指定数量的对话轮，或全部主对话历史。独立执行的完整消息、工具细节和中间结果不得混入主历史；执行结束后，主对话只获得一次明确标识来源 Skill 的摘要，至少说明完成/失败/取消状态、主要结果、实际产生的可见副作用和建议的下一步。独立执行失败或取消同样应回流摘要，主对话仍可继续。

可选指定模型仅影响该 Skill 的独立执行；共享模式继续使用当前主对话模型。指定模型不可用时，独立执行不得静默换用其他模型，应回流可理解的失败说明。

### F6：短命令、参数与热更新

`/skill` 用于列出当前已激活的 Skill，至少显示名称、说明、执行模式和当前参数；没有激活项时明确说明。成功加载过的每个 Skill 自动获得短命令 `/skill:<名称>`，用于由用户直接执行该 Skill。该前缀是固定命名空间，不能覆盖 YuCode 原有命令，也不能与其他 Skill 名称产生歧义。截图中的直接 `/<名称>` 形式在本项目不采用：按已确认的命名冲突规则统一使用 `/skill:<名称>`，从而保留已有 `/review`。短命令支持传入正文参数；参数按 F1 的规则进入 SOP。未加载的 Skill 短命令应提示先加载或显示可用的加载方式，而不是当作普通聊天发送。

Skill 列表、模型可见的名称和说明、加载行为、短命令及已激活的定义都支持热更新：新增、修改、覆盖或移除有效 Skill 后，无需重启即可在下一次相关操作中反映最新状态。正在运行的某次共享或独立执行继续使用开始时已确定的定义；其余后续执行使用新定义。

若已激活 Skill 被有效地删除或被同名高优先级定义替换，YuCode 在下一轮重建时更新到新的有效定义；若没有可替代定义，则解除该 Skill 的激活状态、撤销其专属工具和短命令，并显示中文提示。系统不执行已删除 Skill 的旧 SOP。

执行现有 `/clear` 清屏命令或新建干净会话时，所有已激活 Skill、它们的白名单收窄状态和其自动注册的短命令一并清除；Skill 文件本身不删除。`/clear` 原有的聊天显示与历史保留语义不因本章改变，仅额外清除 Skill 激活状态。恢复一个历史会话不自动恢复此前激活的 Skill，用户需要根据当前可用列表重新加载。

### F7：内置样板

YuCode 随应用提供 `commit`、`review`、`test` 三个可被更高优先级定义覆盖的有效内置 Skill 样板。它们在未覆盖时出现在启动阶段的可用 Skill 摘要中，并拥有中文的一句话说明和可实际执行的 SOP。

`commit` 采用共享模式，用于在当前对话中检查并提交用户明确要求的改动；`review` 和 `test` 采用独立模式，分别回流改动审查摘要和测试摘要。三个样板的工具范围遵循本章白名单规则，不因其内置身份获得额外权限。它们的短命令分别为 `/skill:commit`、`/skill:review`、`/skill:test`，与现有 `/review` 命令共存。

### F8：从 URL 安装第三方 Skill

YuCode 提供系统级 `InstallSkill` 能力，可从用户明确提供或授权的单个 URL 获取第三方 Skill 能力包，验证其入口、资源和专属工具描述后安装到用户层 Skill 存放位置。安装成功后无需重启即可参与三层发现与覆盖，并可按通常流程加载；项目级同名 Skill 仍优先。

下载、读取、解包或校验失败时，必须显示中文原因，保留原有已安装 Skill，不留下可发现的半成品。安装得到的 Skill 仍须通过 F2 的解析和工具白名单校验，不能因来自 URL 而绕过权限、白名单或安全限制。`InstallSkill` 属于系统级能力，不受当前 Skill 白名单限制，但仍沿用 YuCode 对下载和文件写入的既有授权规则。

## 非功能需求

- N1：所有用户可见提示、跳过信息和启动失败原因使用中文，并说明可采取的后续操作。
- N2：Skill 发现、覆盖、解析、加载、白名单收窄、执行模式和热更新的行为可通过替代界面和模拟工具验证，无需依赖完整终端渲染。
- N3：热更新不得使正在执行的任务混用新旧定义；一个执行中的任务始终使用其启动时的完整快照。
- N4：独立执行的隔离边界必须保留主对话可用性，不能让独立任务的完整过程污染主历史或阻塞后续恢复。
- N5：Skill 不新增绕过权限、绕过计划模式、市场分发或自动联网下载的通道；专属工具与现有工具适用同等权限和安全限制。

## 不做的事

- 不提供 Skill 市场、在线搜索、发布、签名、版本号、依赖解析或自动更新；仅支持 F8 中用户指定 URL 的单个能力包安装。
- 不提供图形化 Skill 编辑器、Skill 执行历史浏览器或跨设备同步。
- 不允许一个 Skill 在运行中修改另一 Skill 的定义、白名单或模型配置。
- 不为未激活 Skill 预先注入完整 SOP 或注册其专属工具。
- 不改变现有普通命令的名称与语义；尤其不以 Skill 替代已有 `/review`。
- 不承诺独立执行能撤销其已获授权的外部副作用；摘要只如实回报可见结果。

## 验收标准

- AC1（F1）：分别准备单文件 Skill 和含入口、专属工具描述、实现脚本的目录 Skill；启动后两者均以名称和一句话说明出现在可用摘要中，目录内的辅助文件不会单独出现。分别调用带参数和不带参数的 Skill，模型收到替换后的 SOP，未提供参数时占位符为空。
- AC2（F1、F2）：在三层来源分别提供同名 Skill，验证仅使用项目级定义；移除项目级后使用用户级，再移除用户级后使用内置定义。有效 Skill 名称重复或名称不合法的文件被跳过且有中文警告，其他 Skill 仍可使用。
- AC3（F2）：分别制造损坏 YAML、缺少必填元信息、空正文、损坏目录工具描述和无效脚本引用；每个损坏 Skill 都被跳过并报告原因，YuCode 仍能启动、列出并加载其他有效 Skill。
- AC4（F2、F4）：为一个有效 Skill 配置不存在的普通工具名称，为另一个目录 Skill 配置不存在的专属工具名称；每次启动均在进入交互前失败，中文错误中包含 Skill 和无效工具名称。修正后正常启动。
- AC5（F3）：启动一个新对话，检查模型初始环境只有每个 Skill 的名称和一句话说明，没有任一正文或未激活专属工具；通过系统级加载工具加载一个 Skill 后，完整 SOP、参数和专属工具可用。加载不存在的 Skill 不改变已经激活的 Skill。
- AC6（F3、F4）：依次激活两个工具白名单不同的 Skill，验证每轮环境中两个完整 SOP 均存在且清晰标识；普通可见工具是两个白名单的并集，未列工具不可调用。无论白名单如何设置，系统级加载工具始终可调用，原有权限确认仍然生效。
- AC7（F5）：执行共享模式 Skill，验证调用、工具细节和回复留在主历史且后续对话可引用；执行独立模式 Skill，验证其按声明带入指定历史范围，主历史只新增一次包含状态、结果、副作用和下一步的摘要，不出现独立任务的中间消息或工具细节。失败和取消时也各获得一次摘要且主对话继续可用。
- AC8（F5）：为独立模式 Skill 声明一个不可用模型，执行后验证主历史收到说明模型不可用的失败摘要，且没有静默切换模型或污染主历史。
- AC9（F6）：激活两个带不同参数的 Skill 后执行 `/skill`，验证仅列出已激活项、显示名称、说明、模式和参数。执行 `/skill:<名称> 参数内容`，验证按该 Skill 模式执行并正确替换参数；未加载 Skill 的短命令不进入普通聊天，而是给出加载引导。`/skill:review` 与现有 `/review` 分别可执行，互不覆盖。
- AC10（F4、F6）：在应用运行期间新增、修改、删除和跨层覆盖 Skill；不重启应用，下一次列表、加载和短命令操作均使用新状态。正在执行的任务使用旧快照完成；已激活 Skill 被删除且无替代时，下一轮解除激活并撤销其工具和短命令。
- AC11（F4、F6）：修改一个已激活 Skill 为无法解析的定义，验证后续对话继续使用最后一次有效定义并显示警告；再提供有效定义后，下一轮使用更新内容和工具范围。
- AC12（F6）：激活至少两个 Skill 后执行 `/clear` 和新建会话，验证完整 SOP、白名单收窄状态及 `/skill:` 短命令均被清除，而 Skill 文件保持不变；`/clear` 后原有聊天历史保持其既有行为。恢复历史会话后不自动恢复激活状态。
- AC13（F7）：未提供覆盖定义时，启动后可发现 `commit`、`review`、`test`；分别执行它们，验证 `commit` 的过程留在主历史，`review` 与 `test` 只回流独立摘要，且均遵循既有工具权限。
- AC14（F8）：通过 `InstallSkill` 从一个有效 URL 安装第三方目录 Skill，验证无需重启即可被发现、加载并执行，且项目级同名定义仍优先。再分别提供无法下载、损坏内容和不合法工具白名单的 URL，验证显示原因、现有 Skill 仍可用、没有半成品，并且安装过程遵循既有授权。
- AC15（整体）：在 tmux 中启动 YuCode，完成“查看可用 Skill → 加载一个项目级目录 Skill → 以 `/skill:<名称>` 带参数执行 → 用 `/skill` 查看激活项 → 再加载一个 Skill 验证白名单并集与建议工具提示 → 执行内置 `/skill:test` 并查看摘要 → 修改 Skill 后再次执行 → `/clear` 并验证激活状态清除”的真实端到端流程；记录每一步实际可观察结果并对照本章验收标准。
