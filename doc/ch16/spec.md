# 子 Agent 与后台任务 Spec

## 背景

YuCode 目前只有主 Agent 负责整段对话与工具调用。面对需要独立探索、规划或长时间执行的子任务时，主对话会积累大量中间过程，也无法以角色、权限和工具范围隔离任务。本章需要让主 Agent 能通过一个稳定的统一工具委派子任务，并在不干扰主对话的前提下获取结果。

子 Agent 分为两类：定义式子 Agent 从预设角色和空白对话开始；Fork 式子 Agent 继承发起者的完整对话历史，以便复用已有上下文与请求缓存。两类运行都必须有独立的运行时状态、可追踪的父子关系，以及可被用户查看和取消的后台任务。

## 目标

- 支持以 Markdown 正文和 YAML frontmatter 声明可复用的 Agent 角色，并按既定优先级加载和覆盖。
- 向主 Agent 提供一个工具名称固定的委派入口，能够启动定义式或 Fork 式子 Agent。
- 支持子 Agent 独立、非交互地执行至完成，并将结果异步通知回主对话。
- 对子 Agent 实施分层工具限制，避免越权操作和无限嵌套。
- 提供后台任务状态管理、链路追踪和对应的交互命令。
- 内置 Explore、Plan 和 general-purpose 三个可直接使用的角色。

## 功能需求

### F1：Agent 定义格式与加载

系统应支持以“YAML frontmatter + Markdown 正文”定义 Agent。frontmatter 至少能够声明角色名称、用途说明、可用工具限制、禁止工具限制、模型选择、最大执行轮次和权限模式；模型选择只能是继承当前模型、haiku、sonnet 或 opus 之一。正文作为角色在整个生命周期内持续可见的工作指令。

定义从以下目录加载：项目级 `.yucode/agents/`、用户级 `~/.yucode/agents/`、内置定义目录和已加载插件内的 `agents/` 目录。定义同名时，项目级覆盖用户级，用户级覆盖内置级，内置级覆盖插件级。无法解析或字段不合法的定义必须被报告为中文且可定位的错误，不能悄悄以默认含义继续运行。

### F2：统一 Agent 委派工具

主 Agent 始终向模型提供同一个 Agent 委派工具。工具通过 `subagent_type` 参数区分：指定已加载角色名称时走定义式路径；指定 Fork 类型时走 Fork 路径。工具以 `run_in_background` 参数让调用方明确选择是否立即转入后台；工具的名称和参数形状不因当前加载了哪些角色而改变。

定义式调用必须要求目标角色存在，并把用户任务交给该角色；Fork 调用必须携带明确的子任务说明。调用参数无效、目标不存在或当前上下文不允许委派时，应把清楚的失败原因返回给主 Agent，使其能够调整后续行为。

### F3：定义式与 Fork 式运行隔离

定义式子 Agent 必须从不含父对话消息的空白对话启动，并附带其角色正文。Fork 式子 Agent 必须继承父 Agent 发起时的完整对话历史和可用工具上下文，使其首次模型请求能够复用相同前缀的请求缓存。

每个子 Agent 必须拥有独立的消息状态、权限状态、文件读取缓存和用量计数；LLM 客户端、Hook 引擎和受项目根目录约束的文件系统基础能力可在符合现有安全语义的前提下共享。子 Agent 的内部过程不得自动写入父对话；父对话只接收规定的任务通知与最终摘要。

### F4：跑到底执行与结果回传

子 Agent 必须以非交互的“跑到底”方式执行：模型继续请求工具时执行下一轮；模型不再请求工具时视为完成。角色配置的最大轮次、取消、模型或工具错误也必须以可辨识的终止状态结束。

子 Agent 完成、失败、取消或超时时，系统应生成包含任务标识、状态、结果摘要和用量信息的异步通知，并以 `task-notification` 形式自动注入主 Agent 后续可见的对话上下文。主 Agent 不应被子 Agent 的运行过程阻塞，也不应直接接收其完整私有消息历史。

### F5：多层工具过滤与嵌套限制

子 Agent 的可调用工具必须同时受以下限制约束：全局禁止项、角色自定义允许/禁止项、后台任务白名单、Agent 定义中的工具声明，以及角色权限模式。多个限制相冲突时，应采用更严格的结果。工具即使通过上述筛选，仍必须遵循既有权限确认；当当前角色权限不能直接允许某项调用但该调用可由用户授权时，应进入既有 TUI 权限确认，而不是绕过权限或静默执行。

系统必须防止子 Agent 无限制再创建子 Agent。默认情况下，子 Agent 不得继续委派新的子 Agent；若某一受控场景被允许，仍须受所有工具过滤规则约束。被过滤的工具调用不得执行，并应向子 Agent 返回可理解的拒绝原因。

### F6：后台任务管理

系统应管理后台子 Agent 的任务标识、来源、状态、开始与结束时间、结果摘要、错误信息、取消能力及用量。定义式调用可通过 `run_in_background` 显式选择后台执行；未显式后台的前台运行满 120 秒时必须自动转为后台；用户可在执行中通过 ESC 将可切换任务转入后台。Fork 式调用必须始终作为后台任务执行。

后台任务达到其时限后必须被自动停止，并以超时状态通知父对话。取消已结束的任务或不存在的任务应返回清晰结果且不能影响其他任务。

系统应在任务开始、停止、完成以及向主对话发送通知时分别产生 TaskStart、TaskStop、TaskComplete、SendMessage 四种任务生命周期事件。事件应带有可识别任务及状态所需的上下文，供已有 Hook 系统观察；事件处理失败不得改变任务的既有终止或通知语义。

### F7：父子链路追踪

系统应在当前应用会话内记录每个委派的调用链：父任务或主对话、子任务、调用类型、所用角色（如有）、执行状态、开始与结束时间，以及每层和聚合的 token 用量。用户能够从任务信息中识别某个任务由谁发起及其后代任务的资源消耗。

追踪数据只要求在当前运行期间可用，不要求跨会话恢复；任务完成或失败后仍应保留至本次应用结束，供查询和通知使用。已有 Skill 的 Fork 执行路径也必须经由同一套子 Agent 创建、运行、工具限制、任务管理、通知与追踪能力，不得维持独立的子 Agent 执行通道。

### F8：任务 Slash 命令

系统应提供 `/tasks`、`/task info` 和 `/task cancel` 命令。`/tasks` 列出当前会话的活动和最近结束任务，并显示足以区分任务的标识、状态、类型、角色和用量摘要。`/task info <任务标识>` 显示指定任务的详细状态、父子链路、时间、结果或错误摘要与 token 用量。`/task cancel <任务标识>` 请求取消仍在运行的任务。

命令缺少任务标识、标识无效或任务状态不支持取消时，界面必须用中文说明原因。任务命令本身不得发送给模型。

### F9：内置 Agent 角色

系统应随应用提供以下三个内置定义，且它们与用户/项目定义遵循同一覆盖规则：

- Explore：使用 haiku 模型，仅可进行只读探索，输出发现与相关位置。
- Plan：仅可进行只读分析和规划，不得修改项目或执行有副作用操作。
- general-purpose：具备允许范围内的完整能力，用于一般独立子任务。

三个角色的用途、工具边界、权限模式和工作指令必须可从其定义中读出；被项目级或用户级同名定义覆盖后，委派工具应使用覆盖后的角色。

## 非功能需求

- N1：所有用户可见的定义加载错误、工具拒绝、任务状态、超时、取消与 Slash 命令反馈均使用中文，并包含可定位的角色名、任务标识或字段信息。
- N2：定义解析与优先级、两类委派、状态隔离、运行至完成、工具过滤、后台控制、追踪、通知和命令均应有自动化测试，不依赖真实模型服务。
- N3：子 Agent 的异常、超时和取消不得导致主 Agent 会话崩溃、丢失消息或停止响应。
- N4：Fork 式首次请求应保留父对话的相同前缀及工具上下文，不插入会破坏该前缀复用的额外历史消息；这一要求以请求内容可验证为准，不承诺特定模型服务商的计费结果。
- N5：本章不降低现有权限、Hook 或项目目录安全边界；共享基础设施不能使子 Agent 获得父 Agent 未有的额外能力。

## 不做的事

- 不提供 Worktree 或其他文件系统级隔离。
- 不提供多个子 Agent 之间的团队编排、共享任务图或协作协议。
- 不持久化 Trace、后台任务或任务通知到跨应用会话的存储。
- 不新增图形化任务管理界面、远程任务执行器、排队调度、重试策略或任务优先级。
- 不保证不同模型供应商一定提供或计费 prompt cache；仅保证 Fork 请求保留可缓存的前缀。

## 验收标准

- AC1（F1）：在项目级、用户级、内置级和插件级分别放置同名与不同名定义后加载，验证全部有效定义可用，且同名定义按“项目 > 用户 > 内置 > 插件”覆盖。提供缺失 frontmatter、未知字段和非法字段值（包括模型值不在继承、haiku、sonnet、opus 内），验证加载时得到中文且可定位的错误。
- AC2（F2）：检查主 Agent 的工具清单，验证无论角色数量如何变化都只暴露同一个 Agent 委派工具，且该工具带有 `subagent_type` 和 `run_in_background`。分别以已存在角色和 Fork 类型调用，验证进入对应路径；验证定义式任务可由 `run_in_background` 显式进入后台；以未知角色、缺少任务说明和不允许的嵌套调用，验证工具结果包含中文失败原因且不创建任务。
- AC3（F3）：启动定义式子 Agent，验证其初始模型请求不含父对话消息、含角色工作指令；启动 Fork 子 Agent，验证其初始请求保留父对话与工具前缀。分别改变子 Agent 的消息、权限、读缓存和用量，验证父 Agent 对应运行时状态未被改变。
- AC4（F4）：使用可控模型依次要求工具后给出最终回复，验证子 Agent 持续执行至模型不再调用工具并生成最终通知。验证通知以 `task-notification` 自动进入主 Agent 后续可见上下文，而不带入子 Agent 私有历史。分别模拟达到轮次上限、模型错误、取消和超时，验证每种情况有明确终止状态、摘要和用量信息，且主 Agent 仍可继续对话。
- AC5（F5）：分别配置全局禁止、角色允许/禁止、后台白名单、定义层工具限制和角色权限模式，验证每层都能阻止对应工具，交集规则采用最严格结果，且被阻止工具从未实际执行。验证未被过滤但需要用户确认的调用进入既有 TUI 确认流程。验证子 Agent 不能继续创建子 Agent，并收到中文拒绝原因。
- AC6（F6）：验证 `run_in_background` 显式后台、前台运行满 120 秒自动后台、ESC 手动转后台三种方式均创建或转换为可查询任务；验证 Fork 总在后台。让后台任务超时和取消，验证其停止、状态更新及异步通知；验证 TaskStart、TaskStop、TaskComplete、SendMessage 事件各自在对应时机发生且不会被事件处理失败改变。验证对不存在或已结束任务取消不会影响其他任务。
- AC7（F7）：创建包含至少一层父子关系的任务，验证任务详情显示正确父子链路、调用类型、角色、状态、时间、各层 token 用量与聚合用量；从 Skill 的 Fork 路径启动任务，验证其同样可由任务命令查询、受相同工具限制并产生相同追踪和通知。任务完成后仍可在本次应用运行中查询，重启后不要求保留。
- AC8（F8）：在终端分别执行 `/tasks`、`/task info <任务标识>` 与 `/task cancel <任务标识>`，验证列表、详情和取消结果正确显示，且命令未发给模型。验证缺少或非法任务标识以及取消不可取消任务时得到中文反馈。
- AC9（F9）：加载内置角色后分别委派 Explore、Plan 和 general-purpose，验证 Explore 使用 haiku 且无写入能力，Plan 无副作用能力，general-purpose 可使用允许的完整工具集；再以高优先级同名定义覆盖一个内置角色，验证后续委派使用覆盖定义。
- AC10（整体）：在 tmux 中启动 YuCode，输入一个真实的“先探索再给出结论”的请求，观察主 Agent 发起子 Agent 委派、子 Agent 在后台完成、主对话收到通知并给出后续回复；同时用 `/tasks` 和 `/task info` 查看状态与用量，并按照本章 checklist 逐项记录实际结果。
