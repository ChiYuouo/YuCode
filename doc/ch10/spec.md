# 上下文状态展示与窗口保护 Spec

## 背景

YuCode 已具备工具结果外置和历史压缩能力，但当前状态提示无法清楚区分“实际发生了外置/压缩”与“自动检查后无需处理”。当上下文窗口被配置得接近自动安全余量时，首条普通消息也会被判定为接近阈值，并在界面显示“没有可压缩的较早历史”，容易让用户误以为系统每轮都在压缩。

用户希望获得类似终端编程助手的紧凑状态行：外置时展示存盘与释放量，压缩时展示开始和压缩前后的估算 Token；这些状态均使用普通字重。

## 目标

- 仅在实际外置工具结果或实际执行摘要压缩时显示自动上下文状态。
- 用简短、非加粗的中文状态清楚说明外置量和压缩效果。
- 在极小窗口的测试配置下，避免自动检查无可压缩历史时干扰普通对话。
- 保持 `/compact` 的手动反馈能力。

## 功能需求

- F1：单项或单消息工具结果达到外置条件并成功存盘后，界面必须显示一条普通字重状态，包含外置的工具结果数量和本次从对话历史移出的字符数；外置未发生时不得显示该状态。
- F2：自动或紧急重量压缩实际开始生成摘要时，界面必须先显示一条普通字重的“正在压缩上下文”状态；成功后必须显示压缩前与压缩后的估算 Token。没有较早历史、未达到自动阈值或自动熔断时，不得显示“正在压缩上下文”。
- F3：自动检查因没有可压缩较早历史而跳过时，界面必须保持安静，不显示“没有可压缩的较早历史”或等价提示；用户输入 `/compact` 手动触发且没有较早历史时，必须保留清晰的普通字重跳过提示。
- F4：所有新增的外置、压缩开始、压缩完成、手动跳过和失败状态必须使用普通字重，不得以粗体显示；工具调用和普通回复的既有样式不得改变。
- F5：上下文窗口配置继续允许大于 13K 的较小值，以支持压缩逻辑测试。此类配置使自动阈值很低时，系统可以执行自动检查；但没有较早历史可压缩时必须静默跳过，不得生成摘要请求或显示压缩状态。未配置时仍使用 128K 默认值。

## 非功能需求

- N1：状态中的字符数与 Token 数必须来自该次实际处理前后的同一份历史估算，不得虚构或使用累计会话总量。
- N2：显示优化不得改变自动触发阈值、外置路径、摘要内容、工具调用、权限确认或模型请求语义。
- N3：状态文本必须简短、中文且适合终端单行阅读。

## 不做的事

- 不改变现有 50K 单项、200K 单消息外置阈值。
- 不增加精确 tokenizer 或调整摘要策略。
- 不将所有普通的上下文检查显示为调试日志。
- 不改变用户主动输入 `/compact` 的语义。

## 验收标准

- AC1（F1、F4、N1）：触发工具结果外置后，观察到一条非加粗状态，内容包含外置数量和本次释放的字符数；未触发外置的普通工具结果后，观察不到外置状态。
- AC2（F2、F4、N1）：让自动或紧急压缩真正执行。观察到先显示非加粗的“正在压缩上下文”，完成后显示同次历史的压缩前后估算 Token；压缩未实际开始时没有开始状态。
- AC3（F3）：以正常 128K 配置发送首条普通消息，观察不到“没有可压缩的较早历史”；输入 `/compact` 且会话没有较早历史时，观察到该手动跳过提示。
- AC4（F5）：加载 `13001` Token 的测试配置并发送首条普通消息。观察到自动检查可以发生，但由于没有较早历史，既不生成摘要请求，也不显示压缩状态；加载默认 128K 配置时仍正常启动。
- AC5（N2、N3）：运行完整测试套件并在终端执行一次普通工具任务。观察到原有工具行、权限确认、流式回复和压缩行为保持可用，新增状态为简短中文单行文本。
