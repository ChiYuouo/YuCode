# YuCode 五层权限系统 Spec

## 背景

YuCode 已具备基础的工具调用确认、工作目录边界和任务执行策略，但尚不能让用户以统一、可配置且分层的方式控制不同工具及其参数可执行的范围。面对文件修改、命令执行等有副作用操作，系统需要同时防范已知危险命令、路径逃逸和不符合项目约定的工具调用；规则未明确覆盖时，也需要由用户保留最终决定权。

本章建立五层相互补充的权限防御：不可配置放开的危险操作黑名单、项目范围路径沙箱、可配置规则、整体权限模式和人在回路确认。被拒绝的工具调用必须将原因反馈给模型，使 Agent 能调整策略并继续运行，而不是直接终止任务。

## 目标

- 为所有工具调用提供统一、可预测的权限判断结果，防止高危操作和项目范围外的文件访问。
- 让用户能够以用户全局、项目共享和项目本地三层 YAML 规则声明允许或拒绝的工具调用。
- 让用户可整体切换默认、自动接受编辑、规划、绕过确认四种信任模式，同时保留不可绕过的安全边界。
- 在规则未覆盖的有副作用操作前，以一次、本会话和永久三种范围向用户请求决定。
- 让权限拒绝成为模型可理解的工具结果，以便后续轮次改用安全方案或请求用户帮助。

## 功能需求

- F1：系统必须在执行前以固定的危险操作黑名单检查命令类工具调用。黑名单至少覆盖跨 Shell 的明显不可逆或系统级破坏操作：删除根目录、盘符或其他大范围位置及其通配内容，格式化或分区，关机或重启，删除系统目录，以及破坏性 Git 清理。命中黑名单的操作必须拒绝，且不得由权限模式、任何 YAML 规则或人工确认放行。
- F2：系统必须对专用文件工具的读取、写入、编辑及搜索路径进行路径沙箱判断。目标路径必须位于当前项目目录内；判断前必须解析现有符号链接及可解析的路径成分，防止通过符号链接或相对路径逃逸。无法可靠判定在项目目录内的路径必须拒绝。命令工具必须从项目目录启动，但本章不将命令文本扫描或工作目录设置宣称为操作系统级文件沙箱；命令仍受危险操作黑名单、配置规则与人工确认控制。
- F3：系统必须支持 YAML 规则分别由用户全局、项目共享、项目本地三层保存。每条规则以“工具名(模式)”标识匹配对象，并仅声明 `allow` 或 `deny`；例如 `Bash(git \*)` 可允许以 `git ` 开头的 Bash 命令。规则可匹配工具及其适用的参数或路径，且同时支持精确匹配与 glob 匹配。
- F4：系统必须按以下优先级处理同一工具调用的已匹配规则：会话临时规则、本地级规则、项目级规则、用户全局规则。较高层已匹配规则必须覆盖所有较低层规则；同一层存在允许与拒绝规则都匹配时，拒绝必须优先。
- F5：系统必须提供四种整体权限模式。`default` 必须按规则判断，规则未命中的有副作用操作请求人工决定；`acceptEdits` 必须自动允许未命中的项目内专用文件写入和编辑，但未命中的命令仍请求人工决定；`plan` 必须只允许只读工具，拒绝所有有副作用调用；`bypassPermissions` 必须允许未命中的有副作用操作而不请求确认。四种模式均不得绕过危险操作黑名单、专用文件工具路径沙箱或任何已匹配的明确拒绝规则。
- F6：当一个有副作用操作通过黑名单和路径沙箱、又未被规则或当前权限模式直接决定时，系统必须向用户展示该工具调用及其将产生的影响，并提供“仅本次允许”“本会话允许”“永久允许”和“拒绝”四种选择。仅本次允许只适用于当前调用；本会话允许在本次会话的后续调用中生效；永久允许必须只写入当前项目的本地规则，且该规则不应进入版本控制。
- F7：人工确认中的“允许”只能对通过黑名单和路径沙箱检查的调用生效；用户的选择不得改变拒绝原因或隐式放宽其他工具、参数或路径的范围。
- F8：每一次拒绝都必须阻止真实工具执行，并向模型返回结构化、可理解的结果，包含被拒绝的原因和可行的下一步（例如改用项目内路径、使用允许的工具或请求用户确认）。Agent Loop 在收到此类结果后必须继续，允许模型在后续轮次调整工具调用；除既有循环上限或取消条件外，权限拒绝本身不得导致任务终止。
- F9：权限判断必须按固定顺序执行：先危险操作黑名单；对于专用文件工具再执行路径沙箱；随后按优先级匹配配置与会话规则；最后按当前权限模式或人工确认决定。任何允许结果均不得跳过此前适用的拒绝层。
- F10：用户必须能够通过 `Shift+Tab` 在四种权限模式间循环切换，并在终端状态区域观察当前模式。切换到 `plan` 时，系统必须使用既有只读规划能力；切回其他模式后恢复相应模式可用的工具范围。
- F11：对不产生副作用的调用，系统应保持既有只读能力；本章新增权限行为不得破坏工具调用回灌、命令确认或 Agent 多轮执行的正常流程。

## 非功能需求

- N1：相同的权限模式、规则集合、项目范围和工具调用必须得到确定性的判断结果；规则来源、命中规则（如有）和拒绝层级必须可供界面或测试观察。
- N2：规则加载失败、YAML 格式无效、规则格式不合法或路径无法解析时，系统不得默认放行；应给出明确、可操作的错误说明，并保留其他有效且更高优先级的安全约束。
- N3：用户全局、项目共享、项目本地及会话临时规则的作用范围必须彼此隔离。项目本地规则及由“永久允许”生成的内容必须不进入版本控制；项目共享规则可由项目维护者选择提交。
- N4：危险操作黑名单，以及专用文件工具的路径沙箱，是硬性边界，不得由配置、权限模式、用户确认或模型文本绕过。
- N5：权限判断与人工确认不得泄露命令或参数中可能出现的敏感信息；展示给用户和回传给模型的信息应仅包含做出决定所需的安全摘要。
- N6：权限模式切换必须立即影响下一次工具调用，状态区域显示必须与实际生效的模式一致。

## 不做的事

- 不限制网络请求、域名、远程服务或模型供应商访问。
- 不设置 CPU、内存、磁盘、执行时长、调用次数或其他资源配额。
- 不建立审计日志、合规报表或历史权限决策查询功能。
- 不提供跨项目同步、远程分发或图形化编辑规则配置的能力。
- 不允许通过任何配置、模式或确认禁用危险操作黑名单或路径沙箱。
- 不把“永久允许”写入用户全局规则或可提交的项目共享规则。

## 验收标准

- AC1（F1、N4）：分别请求各类已列出的高危命令，并在四种权限模式、存在匹配 `allow` 规则、人工选择允许的情况下执行；每次均观察到真实命令未执行、拒绝结果说明命中危险操作黑名单。
- AC2（F2、N4）：尝试让专用文件工具读取、写入、编辑或搜索项目外绝对路径、`..` 路径及指向项目外的符号链接；每次均观察到真实工具未执行且提示项目范围限制。对项目内正常路径的相同类型调用，路径沙箱不应错误拒绝。命令工具的验证应确认其从项目目录启动，并仍通过黑名单、规则或人工确认接受控制，而不将其验证为操作系统级路径沙箱。
- AC3（F3）：分别配置精确规则与 glob 规则，针对工具名、命令参数和文件路径运行匹配与不匹配调用；观察到匹配的 `allow` 或 `deny` 被正确应用，不匹配调用不被该规则误影响。
- AC4（F4、N1）：为同一调用在用户全局、项目共享、项目本地和会话中设置相互冲突的规则；观察到判断依次采用会话、本地、项目、用户全局的最高优先级命中。同层同时匹配 `allow` 和 `deny` 时，观察到拒绝。
- AC5（F5、F9）：在四种权限模式下分别执行无匹配规则的文件写入、文件编辑、命令、明确允许调用与明确拒绝调用；观察到 default 对未命中副作用请求确认，acceptEdits 自动允许未命中文件编辑但仍确认未命中命令，plan 拒绝所有副作用，bypassPermissions 直接允许未命中调用；四种模式下明确拒绝均生效，黑名单与路径沙箱也始终先行拒绝。
- AC6（F6、F7）：在需要确认的模式下对未覆盖的有副作用调用依次选择仅本次允许、本会话允许、永久允许和拒绝；观察到仅本次允许不影响下一次调用，会话允许影响本次会话的同范围后续调用，永久允许只在当前项目本地规则中保存且未进入版本控制，拒绝不执行工具且不扩大其他调用权限。
- AC7（F8）：模拟模型发起被拒绝的工具调用后，再发起符合规则或用户确认要求的替代调用；观察到首次未产生真实副作用、模型收到含原因和下一步的结构化结果、Agent Loop 继续且替代调用可正常完成。
- AC8（F10、F11、N6）：使用 Shift+Tab 连续切换四档模式并分别发起只读探索、文件编辑和命令调用；观察到状态区域依次显示实际模式，plan 只暴露只读工具，其他模式按定义恢复工具范围，命令确认和多轮工具调用保持正常，且无副作用调用不会错误进入人工确认或终止整个 Agent Loop。
- AC9（N2、N5）：分别提供格式错误的 YAML、无效规则和包含模拟敏感参数的待确认调用；观察到系统保守拒绝或请求修正，说明可操作且用户界面与模型回传中不出现模拟敏感值。
