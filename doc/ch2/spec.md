# YuCode 工具系统 Spec

## 背景

YuCode 当前只能与用户流式对话，模型无法直接查看或操作工作目录中的内容。本章为它加入受控的工具系统，使模型能在一次请求内选择并执行一项工作，再依据执行结果生成回复。

## 目标

- 支持 OpenAI 与 Claude 后端使用一致的六项核心工具能力。
- 让模型可读取、写入、修改、搜索工作目录内的内容，以及在用户确认后执行命令。
- 工具成功、失败、超时和用户拒绝均能作为结构化结果交还模型。
- 每次用户请求最多执行一次工具调用，并根据结果生成一次最终回复。

## 功能需求

- F1：模型可获知六项核心工具的用途和可填写参数，并能在回答过程中选择其中一项调用：读文件、写文件、改文件、执行命令、按模式查找文件、搜索代码内容。
- F2：文件读取、写入、修改、查找和搜索均限定在 YuCode 启动时的工作目录及其子目录内；越界请求不得执行。执行命令以该工作目录为起点，并且必须由用户逐次确认。
- F3：读文件、查找文件和搜索代码内容应将可读结果返回模型；写文件可新建或覆盖目标文件。
- F4：改文件必须基于提供的原始内容进行唯一匹配替换；找不到匹配项或存在多个匹配项时，不修改文件，并返回清楚的失败原因。
- F5：执行命令前必须向用户展示请求并等待确认；用户拒绝时不得执行，并把拒绝结果返回模型。写文件和改文件无需额外确认。
- F6：每个工具调用均有执行时限；参数无效、访问受限、执行异常、超时或用户拒绝时，程序不得崩溃，而应生成带状态和可读原因的结构化结果。
- F7：模型发起工具调用时，终端显示工具名称、操作目标及成功或失败摘要，不直接刷出完整文件内容或完整命令输出。
- F8：程序能正确接收流式传输中被拆分的工具参数，并在参数完整后执行工具。
- F9：工具执行结果会加入本次对话上下文，并再次交给模型生成最终回复；该最终回复若再次请求工具，不再执行，以明确的本章限制结束本轮。
- F10：同一轮初始模型响应若请求多项工具，只执行第一项，并将此限制清楚反馈给模型和用户。

## 非功能需求

- 保持现有流式文本回复、多轮上下文和取消能力可用。
- OpenAI 与 Claude 配置切换后，用户无需改变交互方式即可使用工具。
- 工具结果应足够清楚，让模型可以据此纠正下一次请求。
- 文件类工具不允许访问工作目录以外的路径；命令工具依赖用户逐次确认，而非操作系统级沙箱。

## 不做的事

- 自动连续执行多轮或多项工具调用的 Agent Loop。
- 同一轮并行或串行执行多个工具。
- 文件修改前的交互式确认、差异预览或回滚。
- 工作目录外的文件访问、命令执行或权限管理。
- 持久化工具调用历史。

## 验收标准

- AC1：使用 OpenAI 和 Claude 配置分别提问时，模型都能选择并调用六项核心工具中的任一项。
- AC2：模型请求读取、查找或搜索工作目录内内容时，结果会返回模型；请求工作目录外路径时，文件类操作被拒绝且程序仍可继续对话。
- AC3：写文件能创建新文件并覆盖已有文件；改文件仅在原始内容恰好唯一匹配时生效。
- AC4：改文件的原始内容不存在或匹配多次时，文件保持不变，模型收到可理解的失败结果。
- AC5：模型请求执行命令时，终端要求用户确认；确认后执行，拒绝后不执行，二者结果都反馈给模型。
- AC6：工具超时、参数错误或执行异常时，终端显示失败摘要，模型收到结构化失败结果，YuCode 不退出。
- AC7：流式工具参数被拆分传输时，YuCode 能正确合并并执行。
- AC8：一次用户请求最多执行一次工具调用；执行结果回灌后模型能生成最终回复，后续工具请求不会自动继续执行。
- AC9：工具调用期间终端仅展示调用与结果摘要，不展示完整工具输出。
