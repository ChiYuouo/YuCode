# YuCode 品牌迁移与首页锦鲤 Spec

## 背景

当前终端 AI 编程助手以 旧名称 为项目、安装包、命令和配置名称，终端首页也使用小猫字符画。项目作者希望将产品统一为更符合个人风格的 YuCode，并以小锦鲤字符画作为首页视觉标识。旧名称不再需要兼容。

## 目标

- 将用户可见、开发者可见和安装后可用的项目标识统一为 YuCode。
- 让用户通过 YuCode 的命令、配置和帮助信息使用该助手。
- 将终端首页的猫咪替换为清晰可辨的小锦鲤字符画。
- 完全移除旧名称及其冗余入口，避免两个品牌并存。

## 功能需求

- F1：安装后的命令、帮助文字、版本信息、启动标题和终端界面必须使用 YuCode；用户不需要输入或看到 旧名称 才能使用主要功能。
- F2：项目的可导入包、配置文件及示例配置必须使用 yucode 名称；启动时只加载新名称配置，不再识别旧名称配置。
- F3：项目说明、测试描述和其他受版本控制的文本中，与产品相关的名称必须更新为 YuCode 或 yucode；历史提交记录不在本次范围内。
- F4：终端首页必须展示小锦鲤而非小猫的字符画，并与现有欢迎、输入和对话功能正常共存。
- F5：旧包目录、旧命令声明、旧配置样例及其他已被新名称替代的受版本控制项必须移除；不能残留可用的 旧名称 兼容入口。

## 非功能需求

- N1：品牌迁移不得改变既有对话、工具调用、权限模式或配置语义，除名称和首页图案外保持原有行为。
- N2：首页字符画应在常见终端宽度下完整可见，且不造成启动报错或布局错位。
- N3：新增或修改的中文说明和注释必须清晰、准确。

## 不做的事

- 不保留旧命令、旧导入路径或旧配置文件的兼容、自动迁移或重定向。
- 不改动模型提供商、工具能力、权限规则或对话交互设计。
- 不修改历史提交、已发布制品或用户本地未受版本控制的文件。
- 不设计图形化 logo 或新增图片资源；首页标识仅使用字符画。

## 验收标准

- AC1（F1）：安装或从项目运行后，使用 YuCode 对应入口查看帮助并启动；观察到命令、标题、欢迎信息与版本信息均使用 YuCode，正常交互可继续进行。
- AC2（F2、F5）：仅放置新名称配置时启动，观察到配置正常生效；旧名称配置不被加载；项目中不存在旧包目录、旧配置样例或可调用的旧命令入口。
- AC3（F3）：搜索受版本控制的项目文本，观察到没有仍指向当前产品的 旧名称/旧名称 名称；版本控制历史和依赖锁定元数据中的不可避免记录可排除在外。
- AC4（F4、N2）：在终端启动应用，观察到首页显示小锦鲤字符画而非小猫，字符画完整，欢迎、输入与对话区域均可用。
- AC5（N1、N3）：运行现有自动化测试并在终端发起一段真实对话请求，观察到工具调用与回复流程仍正常，界面和项目文本中的新增中文内容清晰无误。
