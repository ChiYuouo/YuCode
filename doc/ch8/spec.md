# MCP 外部工具接入 Spec

## 背景

YuCode 当前只能使用内置工具，用户无法把外部 MCP Server 提供的工具接入同一个工具中心。用户希望在配置中声明本地或远程 MCP Server，使 YuCode 在每次启动时自动发现其工具，并让 Agent 如同调用内置工具一样调用它们。

## 目标

- 支持从用户级和项目级配置中声明多个 MCP Server，并合并得到本次启动使用的 Server 列表。
- 在启动时发现每个可用 MCP Server 的工具并注册到 YuCode 的工具中心。
- 让 Agent 能以统一方式调用内置工具和已发现的 MCP 工具。
- 单个 MCP Server 不可用时，仍可正常使用 YuCode、内置工具和其他可用 Server。

## 功能需求

- F1：系统必须读取用户级配置文件 `%APPDATA%\\YuCode\\yucode.yaml` 与当前项目目录的 `yucode.yaml` 中声明的 MCP Server；项目级中同名 Server 的完整声明覆盖用户级声明，其他 Server 保留。
- F2：每个 Server 必须以名称为 key 声明；系统支持本地 stdio Server 的命令、参数和环境变量，以及远程 Streamable HTTP Server 的地址和请求头。环境变量与请求头中的 `${VAR}` 必须以启动进程的环境变量值展开。
- F3：系统必须在每次启动时与每个已配置 Server 建立独立会话，按 MCP 标准完成初始化握手、工具列表发现和工具调用；请求与响应必须能按请求标识正确配对。
- F4：系统必须把已发现的远端工具注册为可供 Agent 使用的统一工具。对 Agent 暴露的名称必须使用 `MCP__服务器名__远端工具名` 规则，避免不同 Server 及内置工具之间的重名冲突。
- F5：当 Agent 调用已注册的 MCP 工具时，系统必须将调用参数转发给其所属 Server，并将 Server 返回的成功结果或失败信息作为该次工具调用的结构化结果返回给 Agent。
- F6：同一 Server 在本次 YuCode 会话内必须复用已建立的连接；会话结束时必须关闭其本地进程或网络连接。
- F7：某个 Server 在连接、初始化或发现工具时失败时，系统必须继续启动并保留其他可用 Server 与内置工具；终端必须用中文警告说明失败的 Server 名称和原因，且失败 Server 的工具不在本次会话中提供。
- F8：单个已连接 Server 的工具调用失败时，系统必须只让该次调用以失败结果结束，不能中断 Agent 会话、内置工具或其他 Server 的后续调用。
- F9：每次等待 MCP Server 响应的最长时间必须为 30 秒；超过时该次启动或工具调用必须以超时处理，不得无限等待。
- F10：MCP 工具必须纳入 YuCode 现有权限链路；默认模式下，用户明确授权执行后仍须由用户对未命中规则的调用进行确认，并可选择仅本次或本会话允许。

## 非功能需求

- N1：配置格式错误、缺少必要字段、无效地址、无法展开的环境变量或不支持的传输类型，必须给出包含 Server 名称与问题原因的清晰中文提示。
- N2：新增说明、配置注释与面向用户的错误信息必须使用清晰、准确的中文。
- N3：MCP 接入不得改变现有内置工具、权限模式、模型提供商或普通对话的既有语义；现有权限规则、授权判断和会话确认的语义同样适用于 MCP 工具。
- N4：不同 MCP Server 的生命周期和故障必须彼此隔离；一个 Server 的异常不能阻塞或错误关闭其他 Server 的连接。

## 不做的事

- 不支持 MCP 的资源、提示词、采样、完成、日志订阅或其他非工具能力。
- 不提供 Server 健康检查、自动重连、后台重试或故障恢复机制。
- 不支持除 stdio 与 Streamable HTTP 外的 MCP 传输方式。
- 不保留旧的单层配置行为作为 MCP Server 配置的替代格式。
- 不为远端工具重新解释、放宽或绕过 YuCode 现有的权限规则；权限策略维持现有统一工具调用流程。

## 验收标准

- AC1（F1）：分别在用户级和项目级配置中声明不同 Server，并在项目级重复声明一个用户级 Server 后启动。观察到两个来源的非重名 Server 都可用，重复 Server 只使用项目级声明。
- AC2（F2、N1）：使用含 `${VAR}` 的 stdio 环境变量和 HTTP 请求头启动，观察到 Server 收到已展开的值；分别提供缺失字段、未定义变量或无效地址时，观察到包含对应 Server 名称和原因的中文提示。
- AC3（F3）：使用符合 MCP 标准的 stdio 与 Streamable HTTP 测试 Server 启动 YuCode。观察到两个 Server 都完成初始化并发现工具；并发或连续请求的响应均返回到各自发起的调用，不发生串包。
- AC4（F4）：配置两个拥有同名远端工具的 Server，且该名称与一个内置工具相同。观察到 Agent 工具列表中三个工具名称均唯一，远端工具按 `MCP__服务器名__远端工具名` 命名，内置工具仍可调用。
- AC5（F5、F6）：在一个 YuCode 会话中连续调用同一远端工具。观察到参数被正确传递、结果被返回给 Agent，且该 Server 只建立一次连接；退出会话后其本地进程或网络连接被关闭。
- AC6（F7、N4）：同时配置一个可用 Server 和一个在启动阶段失败的 Server。观察到 YuCode 正常进入交互、显示包含失败 Server 名称及原因的中文警告，可用 Server 与内置工具均可调用，失败 Server 工具未出现。
- AC7（F8、N3）：让一个已连接 Server 的工具调用返回错误后继续发起内置工具和另一 Server 的工具调用。观察到失败只作为该次调用的结构化结果返回，后续调用及普通对话均可继续正常完成。
- AC8（F9）：让初始化或工具调用在 30 秒内不返回。观察到该操作在 30 秒上限后以明确的超时结果结束，YuCode 或其他 Server 不会被无限阻塞。
- AC9（F10、N3）：在默认权限模式下让 Agent 请求 MCP 工具。观察到未明确执行授权时调用被拒绝；明确授权后出现与内置副作用工具一致的确认卡片，选择“本会话允许”后相同调用在该会话内可继续执行。
