# Hook 自动化系统 Spec

## 背景

YuCode 已具备会话、轮次、消息、工具调用和权限控制等运行流程，但格式化、审计、通知、外部联动和工具调用前的安全限制仍需由用户或分散逻辑手动处理。项目需要一套声明式 Hook 自动化系统，让用户能够在明确的生命周期时刻，按可选条件自动执行固定动作，并且不会因 Hook 自身失败而中断正常的 Agent 对话。

Hook 的目标是将重复、确定的流程自动化；它不是工作流编排器、持久化任务队列或子 Agent 系统。

## 目标

- 让用户通过“事件 + 可选条件 + 动作”声明自动化规则。
- 覆盖会话、轮次、消息、工具及系统层面的 15 个生命周期事件。
- 让工具执行前的规则可以拒绝调用，并把原因反馈给模型以便调整策略。
- 支持命令、提示词、HTTP 请求和子 Agent 占位四类动作，以及一次性、异步和命令超时控制。
- 从 YAML 配置统一加载并在启动或加载时报告无效规则。

## 功能需求

### F1：Hook 规则与生命周期事件

每条 Hook 规则必须包含一个事件和一个动作；条件可省略，省略时表示该事件发生即触发。规则可以同时包含一次性执行、异步执行和命令超时等适用控制项。

系统必须支持以下 15 个固定事件：

- 会话：`session_start`、`session_end`
- 轮次：`turn_start`、`turn_end`
- 工具：`pre_tool_use`、`post_tool_use`
- 消息：`pre_send`、`post_receive`
- 系统：`startup`、`shutdown`、`error`、`compact`、`permission_request`、`file_change`、`command_execute`

同一事件的多个匹配规则按照它们在配置中出现的顺序处理。未声明规则的事件不产生额外行为。

### F2：条件表达式

Hook 可按事件上下文中的字段设置条件。条件必须支持精确匹配、不等匹配、正则匹配和 glob 匹配四种比较方式；多个条件可选择“全部满足”或“任一满足”之一组合，单条规则内不得混用两种组合关系。

无效的字段引用、操作符、匹配模式或混合组合关系必须使该配置被判定为无效，而不是在运行时静默按其他语义执行。

### F3：上下文变量替换

动作中的可替换文本必须能够读取当前事件的名称、工具名称、文件路径、消息内容、错误内容及工具参数中的指定字段。缺失的上下文字段必须以明确、可预测的空值方式处理，不能泄露其他事件或会话的数据。

条件判断与变量替换读取同一事件快照，保证一条 Hook 在执行期间不会因上下文被后续操作修改而得到前后不一致的数据。

### F4：四类动作

系统必须支持以下动作：

- 命令动作：以替换后的文本执行 shell 命令，可设定超时。
- 提示词动作：将替换后的提示内容加入当前 Agent 后续可见的上下文。
- HTTP 动作：向配置的目标发起 HTTP 请求，并可在请求相关文本中使用上下文变量。
- 子 Agent 动作：本章只提供彻底的占位 stub；配置可通过校验，触发时不创建、不运行子 Agent，也不向模型注入额外提示。

各类动作执行失败时必须记录可诊断信息，且不得中断主 Agent 的正常流程；其他规则仍可继续处理。

### F5：执行控制

标记为一次性的 Hook 在同一次应用运行期间至多成功调度一次；应用重启后该标记重置。异步 Hook 在后台调度，不能阻塞主 Agent 的生命周期推进。命令动作超过其配置的时间限制时必须停止等待并记录超时失败。

可拦截工具调用的 Hook 不允许异步执行；配置中同时声明拦截与异步的规则必须被拒绝。

### F6：工具调用拦截

在 `pre_tool_use` 事件中，Hook 可以拒绝当前工具调用并提供原因。出现拒绝后，该工具不得执行；Agent 必须将拒绝原因作为本次工具调用的结果交给模型，使模型能够选择修改参数、换用工具或给出其他回复。

非拦截事件不能阻止 Agent 主流程，也不能把普通 Hook 失败转化为工具调用失败。

### F7：Agent 生命周期集成

Agent 在会话、轮次、消息和工具处理的相应节点必须触发 Hook。系统级事件在对应运行时行为发生时触发。每次触发都提供与该事件相关的上下文，且不得改变既有会话记录、权限确认和工具执行的原有语义，除 F6 明确允许的工具拒绝外。

提示词动作产生的内容应在当前对话的后续模型请求中可见；其他动作默认不把执行输出当作模型消息追加。

### F8：配置加载与校验

系统从 YAML 加载 Hook 规则，并集中校验事件名、动作类型、必填字段、条件表达式、变量引用以及拦截/异步约束。无效配置必须给出中文且可定位问题的错误信息；不能将错误规则作为部分可运行规则加载。

有效规则的加载结果必须可供运行时直接使用，不要求用户为每次事件触发重复解析配置。

## 非功能需求

- N1：用户可见的配置错误、执行失败和拒绝原因均使用中文，并包含足以定位规则或字段的信息。
- N2：Hook 的解析、条件判断、变量替换、动作调度、拒绝行为和 Agent 集成均应可通过自动化测试验证，不依赖完整终端界面。
- N3：Hook 自身的命令、HTTP 或占位动作失败不得中断正常会话、轮次、消息处理或其他非失败 Hook。
- N4：异步 Hook 的异常必须被捕获并记录，不能成为未处理的后台异常。
- N5：本章新增的 Hook 不得绕过既有权限控制；被允许执行的命令、HTTP 请求或其他外部副作用仍遵循 YuCode 已有的授权边界。

## 不做的事

- 不持久化一次性 Hook 的已执行标记；重启应用后重新计算。
- 不提供 Hook 的显式优先级字段、依赖关系、重试、队列、事务或工作流编排能力。
- 不实现子 Agent 动作的真实创建、运行、回流或资源管理；仅保留可声明、可触发但无实际行为的 stub。
- 不提供图形化 Hook 编辑器、运行历史浏览器、跨设备同步或在线规则市场。
- 不允许 Hook 失败取消会话、轮次或非工具事件的主流程。

## 验收标准

- AC1（F1）：加载一份含多个事件、无条件规则和带条件规则的 YAML；分别触发 15 个事件，验证只运行事件匹配且条件满足的规则，并且同一事件的多条规则按配置顺序处理。
- AC2（F2）：分别验证精确、不等、正则和 glob 比较；验证“全部满足”与“任一满足”各自正确筛选规则。为无效操作符、无效匹配模式、未知字段和混合逻辑关系提供配置，验证加载时获得中文错误且该配置不投入运行。
- AC3（F3）：在工具、文件、消息和错误事件中引用事件名、工具名、文件路径、消息、错误和嵌套工具参数，验证动作实际收到正确替换结果；引用缺失字段时验证结果可预测且不带入其他事件数据。
- AC4（F4）：分别触发命令、提示词、HTTP 和子 Agent 动作。验证命令得到执行、提示词在后续模型请求中可见、HTTP 请求被发送；验证子 Agent 动作不创建任务、不运行 Agent、也不向模型增加提示，并记录其占位处理结果。
- AC5（F5）：为一次性 Hook 连续触发匹配事件，验证本次运行内只调度一次；重建运行时后可再次调度。验证异步 Hook 不阻塞主流程，后台失败被记录；验证超时命令停止等待并记录超时。为可拒绝工具调用配置异步标记，验证加载失败并给出中文原因。
- AC6（F6）：配置一个按工具名称和参数拒绝的 `pre_tool_use` Hook，触发匹配调用后验证工具未执行、模型收到包含拒绝原因的工具结果，并能在下一步调整策略；触发不匹配调用时验证原有工具执行与权限流程不变。
- AC7（F7）：运行一次真实对话，覆盖会话开始与结束、轮次开始与结束、发送消息、接收回复、工具调用前后及一个系统事件；验证每个已配置节点恰好获得对应上下文，普通 Hook 失败不终止对话。
- AC8（F8）：分别提供未知事件、未知动作、缺少动作必填字段、非法条件、非法变量引用及非法拦截/异步组合的 YAML，验证每项在加载时以中文指出规则和问题；提供有效 YAML 后验证无需在事件触发时重新解析且可立即执行。
- AC9（整体）：在 tmux 中启动 YuCode，加载一份真实 Hook 配置并输入需要读写文件或运行命令的对话请求；观察工具调用前的安全 Hook 能拒绝一次危险调用并让模型调整，再完成一次允许调用；同时验证一次提示词或命令 Hook 的可观察结果，并逐项记录本章验收标准的实际结果。
