# 上下文管理 Checklist

> 每项只以实际运行或可观察行为判定；完成开发后记录命令、实际结果与通过状态。

## 轻量工具结果外置

- [ ] 单个工具结果超过 50K 字符时，完整原文被保存到项目内本会话缓存，而发送给模型的历史只保留工具状态、预览、缓存路径和“重新读取”提示。（验证：构造 50001 字符工具输出后发起下一次请求；检查请求历史和缓存文件，按路径读回内容必须逐字相同。）
- [ ] 同一消息工具结果合计超过 200K 字符时，系统从最大结果开始依次外置，直到剩余结果不超过阈值。（验证：构造多个均小于 50K、总量大于 200K 的结果；观察外置顺序和保留结果。）
- [ ] 外置不改变工具成功/失败、工具名、目标和错误码等可观察语义。（验证：分别外置成功和失败结果；后续请求历史仍能识别两者状态。）
- [ ] 新启动 YuCode 时上一会话的外置缓存已清理，本会话可以重新创建缓存。（验证：先写入缓存，重建会话存储；观察旧文件不存在且新的保存正常。）
- [ ] 缓存写入失败时历史保持原状，并向用户显示失败而不是留下半外置结果。（验证：模拟写入异常；比较操作前后历史，观察中文失败状态。）

## 预算、触发与近期原文

- [ ] 上下文窗口默认 128K，可通过配置改写，并且 OpenAI 与 Anthropic 都使用同一个配置值。（验证：分别加载默认和自定义配置，并以两种 Provider 的 Agent 请求前判断验证阈值。）
- [ ] 自动重量压缩仅在估算待发送历史达到“窗口减 13K”后触发，且轻量外置总是在它之前执行。（验证：用 usage 锚点构造临界值上下各一组历史；观察低于阈值不摘要、达到阈值先外置后摘要。）
- [ ] `/compact` 会启动一次手动重量压缩，目标为“窗口减 3K”；没有可压缩旧历史时显示“无需压缩”。（验证：在低于自动阈值的有旧历史会话输入命令，再在只有近期消息的会话输入命令；观察两种中文结果。）
- [ ] 有最近一次 API input usage 时，后续估算只按相对历史字符变化调整；没有 usage 时仍能用字符近似判断。（验证：记录 usage 后追加、删除和替换消息，再比较估算；另在无 usage 会话触发阈值判断。）
- [ ] 重量压缩后保留从尾部向前至少 10K Token 的原始消息，并且不论大小至少保留最近 5 条。（验证：构造足够长的多消息历史后压缩；检查保留尾部与条数。）
- [ ] 较早用户原始要求以逐字内容优先进入压缩结果，系统不改写用户文字；只有为避免上下文硬超限而不得不省略时才不发送该文本。（验证：使用带有独特原句的早期用户消息触发压缩；检查摘要和保留历史的原文。）

## 结构化摘要与边界

- [ ] 摘要请求没有任何可调用工具，且提示明确禁止调用工具。（验证：检查摘要请求的工具集合为空；使用会尝试工具调用的测试 Provider，观察没有工具执行。）
- [ ] 摘要模型输出草稿和正式摘要时，系统只保存正式摘要；草稿不会出现在会话历史、缓存文件或 TUI。（验证：让测试 Provider 返回两段标记输出；分别检查三处内容。）
- [ ] 正式摘要包含九个固定部分：原始用户要求、当前任务目标、已完成工作、验证结果、代码/文件状态、重要决定与约束、最近读文件快照、可用工具与外置资料位置、未完成事项与下一步。（验证：触发摘要并检查九个标题均存在。）
- [ ] 摘要只保留历史可证实的内容，不将它当作代码原文；压缩后历史附有要求重新读取原始文件或缓存、不得臆测细节的边界提示。（验证：在摘要中涉及文件细节后继续任务；观察下一次模型请求含边界提示，并要求读取原资料。）
- [ ] 摘要流格式错误或请求失败时，历史不被替换并返回清晰中文失败状态。（验证：模拟缺失正式摘要标记与 ProviderError；比较压缩前后历史。）

## 失败恢复与熔断

- [ ] 模型返回 `prompt_too_long` 或等价上下文超限错误时，系统紧急压缩后只重试原请求一次。（验证：让 Provider 连续两次返回该错误；观察总共两次普通请求和一次压缩，不发生第三次重试。）
- [ ] 紧急重试前产生的未完成文本或工具调用不会进入会话，也不会执行。（验证：首次请求先输出片段或工具调用再返回超限错误；观察它未展示为完成回复且工具未运行。）
- [ ] 普通网络或服务错误不会触发紧急压缩或重试。（验证：模拟不含上下文超限码的 ProviderError；观察一次失败结束。）
- [ ] 自动或紧急摘要连续失败三次后，自动压缩熔断；成功自动摘要会清零连续失败次数。（验证：连续模拟三次失败、再观察自动摘要被阻止；在另一个会话中失败后成功再失败，观察未提前熔断。）
- [ ] 手动 `/compact` 不计入自动失败次数，也不受自动熔断限制。（验证：触发自动熔断后执行手动压缩；观察其仍发起请求，并检查失败计数不变化。）

## 终端交互与既有能力

- [ ] `/compact` 是本地命令：不显示为普通用户提问、不写入会话历史，也不会作为 Agent 任务发给模型。（验证：在 TUI 输入命令；检查显示、历史和测试 Provider 的普通请求记录。）
- [ ] 手动压缩期间输入被禁用，完成、跳过、失败或熔断后恢复，且每种结果都有中文状态。（验证：在 TUI 中分别模拟四种结果，观察输入控件状态和聊天区提示。）
- [ ] `/compact` 不会被 `/plan`、`/do` 模式菜单拦截或显示为无效模式命令。（验证：输入 `/compact`，观察立即开始压缩而不是显示模式错误。）
- [ ] 原有权限确认、工具调用、流式回复和取消行为保持可用。（验证：运行原有 Agent 与 TUI 测试套件，并在终端中完成一次需要工具的普通任务。）
