# YuCode 首个对话版本 Spec

## 背景

YuCode 是一个命令行 AI 编程助手。本阶段先建立可靠的纯对话基础：用户可在终端与一个配置好的大模型进行连续、实时的对话。

## 目标

- 启动 YuCode 后进入简洁的交互式终端对话界面。
- 支持 Anthropic Claude 与 OpenAI 两类 API 后端。
- 模型回复以流式方式实时显示。
- 在一次程序运行期间保留对话上下文。

## 功能需求

- F1：用户启动程序后，可在终端持续输入消息并获得模型回复。
- F2：模型回复到达时，终端应持续追加显示内容，而不是等待完整回复后一次性显示。
- F3：用户的后续消息应携带本次运行中此前的对话内容，使模型能理解上下文。
- F4：程序通过当前目录的 `yucode.yaml` 读取当前后端配置；配置包含 `protocol`、`model`、`base_url`、`api_key` 四个核心字段，修改 `protocol` 可切换 Claude 与 OpenAI。
- F5：Claude 后端可通过可选配置启用 extended thinking；启用时，思考内容与最终回答应分别实时显示。
- F6：当配置无效、认证失败、网络异常或流式请求中断时，程序应显示易理解的错误，并回到输入状态，允许用户继续对话。
- F7：用户可正常结束交互会话。

## 非功能需求

- 第一版使用 Python 实现。
- 两个后端对上层对话流程提供一致的使用方式，以便后续增加新的供应商。
- 流式传输采用 SSE。
- 对话历史仅保存于内存，程序退出后清空。

## 不做的事

- 工具调用、文件读写、代码编辑或其他 Agent 执行能力。
- 跨重启保存或恢复会话。
- 多配置档案、启动时选择配置档案。
- 复杂分栏终端界面、账号管理或自动重试。

## 验收标准

- AC1：在含有效配置的目录启动程序后，用户能输入问题，并在同一终端看到逐步出现的模型回复。
- AC2：使用 Claude 配置和 OpenAI 配置分别启动时，都能完成一次流式问答。
- AC3：连续发送两条有关联的消息时，第二条回复能正确利用第一轮内容。
- AC4：切换配置中的 `protocol` 后，无须改动交互流程即可使用另一类后端。
- AC5：启用 Claude 思考配置后，终端会先后实时显示可区分的思考内容和正式回答。
- AC6：提供无效密钥或不可访问地址时，终端显示错误后仍可继续接收下一条输入。
- AC7：退出程序后再次启动，不会携带上次运行的对话内容。
