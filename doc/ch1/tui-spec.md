# YuCode Claude Code 风格 TUI Spec

## 背景

原界面使用顶部状态栏和带边框的消息卡片，视觉上更像普通聊天应用，缺少终端 Coding Agent 的紧凑感。

## 目标

- 空会话展示 Claude Code 风格欢迎页；第一条消息发送后切换为聊天工作区。
- 使用深灰终端底色与青蓝强调色，降低边框和卡片感。
- 保持既有 Claude/OpenAI SSE 流式回复、多轮上下文、Claude extended thinking 与取消能力。

## 功能需求

- F1：欢迎页显示单色小猫字符画、YuCode 标题、当前进程工作目录和 Provider/模型；不展示固定示例提示。
- F2：聊天工作区使用可滚动消息区；用户消息以青蓝 `›` 提示符显示，助手回复以无边框 Markdown 增量显示。
- F3：助手消息创建时立即显示“正在思考…”活动提示；Claude thinking 到达后显示默认折叠的轻量区域。思考入口位于正式回答末尾，自动跟随到底部时仍可见；请求结束时隐藏活动提示并保留可展开的思考记录。
- F4：底部使用多行输入框：`Enter` 发送，`Shift+Enter` 换行；`/exit`、`/quit` 正常退出。
- F5：输入框下方显示紧凑状态行：生成状态、Provider、模型、消息数及累计输入/输出 Token。
- F6：生成时禁用输入，`Ctrl+C` 取消当前 HTTP 流；错误以内联消息显示，并恢复继续对话的能力。
- F7：AI 生成及新消息挂载时，界面在内容完成布局后无动画滚动到底部，始终显示最新输出；生成结束后用户可自由浏览历史。

## 非功能需求

- 不修改 Provider 抽象、YAML 配置、SSE 协议和内存会话历史结构。
- 不加入工具调用、文件树、代码 diff、历史会话或会话持久化。
- 窄终端下输入、状态和消息区仍保持可用。

## 验收标准

- AC1：启动时可见小猫欢迎页、目录和 Provider/模型，且不展示固定示例提示。
- AC2：首次发送后欢迎页移除，用户提示符与流式助手 Markdown 出现在同一滚动消息区。
- AC3：`Enter` 发送，`Shift+Enter` 写入换行，生成状态下输入不可编辑。
- AC4：thinking 默认折叠，错误和取消均不会阻塞下一轮输入。
- AC5：状态行准确反映状态、消息数和累计 Token；连续两轮仍携带前文。
